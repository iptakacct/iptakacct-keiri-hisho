# 依頼文の文例集

導入（コンサル）で先方に送る依頼文の型。宛先の役割（経営者・管理者・作業者）ごとに並べる。役割の分け方は `.claude/rules/client-connection-setup.md`「人の役割を最初に決める」。

## 使い方

- **1通に1つの相手・1つの用件。**権限は管理者へ、作業は作業者へ（相手を間違えると往復が増える）
- 画面の操作を頼むときは「どの画面で・何を・どのアカウントに」を URL つきで書く
- 断られた場合・できなかった場合の分岐を1行添える
- 下書きはインスタンスの `work/drafts/` に置き、本文をクリップボードに入れる（`.claude/rules/communication.md`）。送信は本人が行う
- チャット（Lark・Slack 等）で送るときは、冒頭の宛名をメンションにする
- 〈〉はすべて差し替える。〈こちらのアカウント〉は接続に使うこちらのメールアドレス

## 管理者宛

### 権限のまとめての依頼（キックオフの直後）

最初に1通でまとめて頼む（`client-connection-setup.md`「最初の依頼で、権限をまとめて取る」）。送る前に、今の自分の権限を画面で確かめ、足りないものだけを残す。

```
〈管理者〉さん

お世話になっております。経理の自動化の準備として、次の権限の追加をまとめてお願いできますでしょうか。いずれも〈こちらのアカウント〉への追加です。

1. 〈会計ソフト〉：管理者としてのメンバー登録（帳簿・設定・連携の状態を見るため）
2. 〈会計ソフト〉のアプリポータル：ユーザー登録と、アプリ連携（〈使うサービス：会計・請求書・経費・給与〉）・アプリ開発・システム管理
   〈アプリポータルのURL〉 →「ユーザー」
3. 〈受領・請求のツール〉：閲覧の権限
4. 〈チャット〉：ボットの承認（別途ご案内します）

帳簿を書き換えることはありません（読み取りと確認のみです）。権限が強くて気になるものがあれば、その旨お知らせください。用途をご説明のうえ、必要なものだけに絞ります。

よろしくお願いいたします。
〈署名〉
```

### Google Cloud の設定（資料を無人で読むため）

手順の背景は `client-connection-setup.md`「Google ドライブ・スプレッドシート」。

```
〈管理者〉さん

お世話になっております。月次の照合を自動にするため、〈読みたい資料：案件管理のスプレッドシート等〉を読み取る、読み取り専用のシステム用アカウントを作りたいです。
御社の名義で作っておきたいので、最初の2つだけ〈管理者〉さんのアカウントでお願いできますでしょうか。2分ほどで終わります。残りはこちらで進めます。

1. プロジェクトを作る
https://console.cloud.google.com/projectcreate
プロジェクト名に「〈会社の英字名〉-keiri」と入れて「作成」

2. こちらを管理者として追加する
https://console.cloud.google.com/iam-admin/iam
画面上部でプロジェクト「〈会社の英字名〉-keiri」を選ぶ →「アクセス権を付与」
・新しいプリンシパル：〈こちらのアカウント〉
・ロール：オーナー
→「保存」

※2で「このドメインのユーザーしか追加できない」と出た場合は、社外のアカウントを追加できない設定です。その場合はお知らせください。別の手順をお送りします。

よろしくお願いいたします。
〈署名〉
```

### チャットのボットの承認と、グループへの追加

ボットの公開範囲に管理者を入れてから申請する（入れないと管理者が検索しても出てこない）。

```
〈管理者〉さん

お世話になっております。経理の連絡を自動で受け取るため、〈チャット〉のボット「〈ボット名〉」の利用申請を出しました。次の2点をお願いできますでしょうか。

1. 管理画面で「〈ボット名〉」の申請を承認
2. 〈対象のグループ名〉にボットを追加

ボットはメッセージを読むのと、決まったお知らせを送るだけで、ほかの操作はしません。
〈グループの設定で、追加前の履歴が見えない場合は「新しいメンバーが過去の履歴を見られる」設定もお願いします。〉

よろしくお願いいたします。
〈署名〉
```

## 作業者宛

### 定例の作業として CSV を出してもらう

時期は、作業者が当月分の取り込みを終えた後（締めの前）。置き場所は自動で見つけられる所に決める。毎月の依頼は出さず、期限を過ぎても届かないときだけ知らせる。

```
〈作業者〉さん

お世話になっております。〈受領・請求のツール〉には外部から読む口が無いため、毎月の定例の作業として CSV を出していただけますでしょうか。

・出すもの：〈メニューと形式：例「経理DL」の標準形式〉
・時期：毎月、当月分の取り込みを終えた後（目安：〈第N営業日〉まで）
・置き場所：〈Google ドライブのフォルダ、またはチャットへの添付〉

置いていただければ、こちらで自動で読み取ります。毎月の依頼はお送りせず、期限を過ぎても見当たらないときだけお知らせします。
ご都合の良い時期・置き場所があれば教えてください。

よろしくお願いいたします。
〈署名〉
```

### マスタ（補助科目・取引先）の名前の方針の確認

名前を直す作業はこちらで行う。作業者には方針だけを聞く（`.claude/rules/monthly-onboarding.md`「マスタの整備」）。

```
〈作業者〉さん

お世話になっております。月次の照合を自動にするにあたり、〈会計ソフト〉の補助科目の名前を、〈元データ：請求先マスタ・発注先マスタ等〉の名前にそろえたいと考えています。作業はこちらで行いますので、進め方だけ確認させてください。

1. 補助科目の名前を、こちらで変更してもよろしいでしょうか（例：「〈今の名前〉」→「〈そろえる名前〉」、〈N〉件ほど）。
　名前の変更は過去の仕訳にもそのまま反映され、金額は変わりません。
　気になっているのは、CSVの取り込みや連携が、補助科目の名前で相手を当てているかどうかです。名前を変えると取り込みで別の補助科目ができてしまう場合は、取り込み側の設定もあわせて直します。

2. 〈まとめ型の補助科目：例「諸口」〉について
　今後は相手ごとの補助科目に分けたいのですが、まとめている理由（取り込みの都合など）があれば教えてください。過去分はそのままで大丈夫です。

3. 今後、補助科目は元データの名前で作る形でよろしいでしょうか。

よろしくお願いいたします。
〈署名〉
```

### 使い方の説明（レクチャー）の日程

```
〈作業者〉さん

お世話になっております。試運転の1か月が終わりましたので、毎月の流れと、自動で届くお知らせの見方をご説明する時間をいただけますでしょうか（〈N〉分ほど）。

・内容：毎月の作業の順番、自動で出る確認・レポートの見方、お知らせが届いたときの対応
・候補：〈日時の候補を3つ〉

よろしくお願いいたします。
〈署名〉
```

## 経営者宛

### 導入の開始と体制の確認

```
〈経営者〉さん

お世話になっております。経理の自動化の導入を始めるにあたり、進め方と体制をまとめました。
〈導入の流れのページのURL〉

体制は次のように考えています。違っていればお知らせください。
・ツールの権限：〈管理者〉さん
・経理の作業：〈作業者〉さん

切り替えまでの間はテスト期間として、帳簿は書き換えず、読み取りと確認・報告だけを行います。

よろしくお願いいたします。
〈署名〉
```

### 試運転の結果の報告と、切り替えの相談

```
〈経営者〉さん

お世話になっております。〈月〉の締めで試運転を行いましたので、結果をご報告します。
〈経理の全体図のページのURL〉

・自動で回るようになったこと：〈要点を2〜3行〉
・人の作業として残るもの：〈要点〉
・見つかったこと：〈二重計上・計上漏れ・税務の気づきなど、判断が要るもの〉

御社の環境への切り替えと、〈作業者〉さんへのご説明の日程を相談させてください。〈打ち合わせの候補〉

よろしくお願いいたします。
〈署名〉
```
