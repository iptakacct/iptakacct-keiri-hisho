# keiri-hisho 設計メモ

## 何を解決するか

会計事務所・経理BPO事業者が複数クライアントの記帳・月次・連絡対応を少人数で回すとき、時間の大半は「確認済みパターンの繰り返し」と「複数システム・複数Slackの横断確認」に消える。keiri-hishoはClaude Codeの上に、その繰り返しを安全に自動化し、判断が必要なものだけ人に回す仕組みを作る。

## 全体構造

- **ルート**：全クライアント共通の行動規範（CLAUDE.md・rules）、スキル、hooks
- **インスタンス**：クライアントごとのフォルダ。事実情報（`context/`）と作業ファイル（`work/`）だけを持ち、スキルは親から継承する
- Claude Codeは起動ディレクトリから親をたどってスキルを読むため、クライアントフォルダで起動すればそのクライアントの文脈＋共通スキルが揃う

## 自動化の原則

1. **確立済みパターンのみ自動化**：`accounting-rules.md`に記録済みのものだけを無確認で登録し、それ以外は「要確認」
2. **1件登録→確認→次の1件**：まとめて登録して後から気づく事故を防ぐ
3. **IDは会社ごとに取り直す**：勘定科目・補助科目・税区分のIDは会社ごとに別物
4. **消込は計上時と同じ補助科目・取引先**：金額一致だけで決めない
5. **過去仕訳を先に見る**：自分の推論より、同じ摘要の過去の処理が信頼できる

## 安全装置

- **hooks（強制）**：許可リスト外のgit push/clone、認証ファイルの読み取り、DLして即実行をブロック
- **rules（お願い）**：機密の扱い、プロンプトインジェクション対策、対外送信は下書きまで
- **leak-scan**：固有情報・秘密のコミットを機械的に拒否（`tools/leak-scan.py`、pre-commit）
- **通知**：5分以上の作業の完了・入力待ちをデスクトップ＋Slackへ通知し、離席を可能にする

## 会計システムとの接続方式

| システム | 方式 | 制約 |
|---|---|---|
| マネーフォワード クラウド会計 | 公式MCP（`mfc_ca`）、claude.aiカスタムコネクタ | 1接続＝1事業者。切替は人が`/mcp`で操作。無人実行不可 |
| freee会計 | OAuthプライベートアプリ＋自前スクリプト | 無人実行可。ただしAPIに「明細の消込」が無いため、登録はfreeeの自動登録ルールに任せ、APIは設定と監視に使う |
| invox（請求書） | OAuth＋自前スクリプト | 認証基盤まで。承認自動化はクライアントごとに基準を確立してから |

## 上流からの還流

開発元の実運用リポジトリでの改善を、固有情報を除いて取り込む仕組み（`upstream/`）。自動コピーではなく、差分を読んで汎用化し、leak-scanで検証する半自動。詳細は`upstream/README.md`。

## 今後の拡張候補

- 定時サマリー（1日数回、全クライアントの要対応事項を全体通知チャンネルへ）のクロスプラットフォーム版

- クライアントSlackの常設Bot（投稿の収集、承認リマインド）
- 非エンジニア向けの対話式インストーラー
- 決算・申告（税務）領域のスキル
