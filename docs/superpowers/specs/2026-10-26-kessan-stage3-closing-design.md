## 1. 目的

段階2までで「資料→帳簿（journal.csv）」ができた。段階3では、その帳簿から

1. 決算整理仕訳を作って登録し（未払・前払・減価償却など）、

3. 達人シリーズがそのまま取り込めるXML（MF・freeeが出しているのと同じ形）を出す

ところまでを行う。あわせて、消費税の**課税事業者**の会社も扱えるようにし、消費税の達人用のXMLも出す。

## 3. 3a：課税事業者対応の帳簿

### 3.1 会社の消費税の設定

年度フォルダの `period.yaml` に `消費税` を足す（`init` に引数を足し、無ければ免税として扱う）。

```yaml
消費税:
  区分: 課税          # 免税 ／ 課税（免税なら以下は書かない）
  方式: 原則          # 原則 ／ 簡易 ／ 2割特例
  計算: 割戻し        # 割戻し ／ 積上げ（売上税額の計算。仕入も同じ方式とする）
  控除: 全額控除      # 全額控除 ／ 個別対応 ／ 一括比例配分（方式=原則のときだけ）
  少額特例: false     # true なら税込1万円未満の課税仕入を 少額特例 にする
```

税込経理だけを扱うので、経理方式のキーは持たない。

- 年度ごとに持つのは、課税／免税・方式が年度で変わるため。根拠（届出・前々期の売上）は `context/company/tax-profile.md` に人が書く
- 免税の年度は、税区分の列をすべて空のままにしてよい（今までの帳簿がそのまま有効）

### 3.2 帳簿の列

journal.csv・adjustments.csv・staging.csv の末尾に次の列を足す（既存の列の位置は変えない。既存ファイルは、列が足りなければ空として読む）。

| 列 | 値 |
|---|---|
| 借方税区分 / 貸方税区分 | 下表のいずれか。空は「消費税の対象外の科目」（預金・未払金など）か、免税の年度 |
| 借方インボイス / 貸方インボイス | 課税仕入のときだけ：`適格` ／ `経過80` ／ `経過70` ／ `経過50` ／ `経過30` ／ `少額特例` ／ `なし` ／ `制度前`（インボイス制度〈2023-10-01〉より前の取引。全額控除） |
| 借方個別対応 / 貸方個別対応 | 個別対応方式の年度の課税仕入のときだけ：`課税対応` ／ `非課税対応` ／ `共通` |

税区分の値（PL科目・資産の取得に付ける）：

| 税区分 | 意味 |
|---|---|
| 課税売上10% / 課税売上8%軽 | 課税売上（標準税率／軽減税率） |
| 免税売上 | 輸出免税 |
| 非課税売上 | 受取利息・土地の譲渡など |
| 非課税資産輸出 | 非課税資産の輸出等 |
| 課税売上返還10% / 課税売上返還8%軽 | 売上値引・返品 |
| 課税仕入10% / 課税仕入8%軽 | 課税仕入（経費・資産の取得） |
| 課税仕入返還10% / 課税仕入返還8%軽 | 仕入値引・返品 |
| 非課税仕入 | 保険料・支払利息など |
| 対象外 | 給与・租税公課・減価償却費など不課税 |
| 貸倒10% / 貸倒8%軽 / 貸倒回収10% / 貸倒回収8%軽 | 貸倒れ |

- 金額は今までどおり**税込**で書く（税込経理）。税抜額・税額は列に持たず、集計の時にスクリプトが計算する
- 旧税率（8%・5%・3%）・輸入・特定課税仕入は段階3では扱わない（XMLの該当欄は空で出す）

### 3.3 科目マスタ

`accounts-master.csv` に `既定税区分` 列を足す（売上高＝課税売上10%、受取利息＝非課税売上、給料手当＝対象外、消耗品費＝課税仕入10% など）。会社ごとの例外は `kessan-patterns.yaml` の確立済みパターンに税区分も書けるようにする。

### 3.4 取り込み・承認での扱い

- 読み取り結果（extracted JSON）に、税率（10／8）と登録番号（T＋13桁）の有無を書ける項目を足す。領収書・請求書の「8%対象」「※軽減税率」の表示はAIが読む
- 仕訳候補を作るとき、課税の年度なら税区分を「パターン → 科目の既定税区分」の順で埋める。インボイスは、証憑に登録番号があれば `適格`、無ければ取引日から経過措置の区分を決める。区切りと割合はコードに書かず `config/consumption-tax/invoice-transition.yaml` から読む（根拠URL・確認日付き）。2026-10-26 時点の内容（令和8年度改正後、国税庁の資料〈`config/consumption-tax/invoice-transition.yaml` の根拠URL・確認日2026-10-26〉で確認済み）：〜2026-09-30 は80%、2026-10-01〜2028-09-30 は70%、2028-10-01〜2030-09-30 は50%、2030-10-01〜2031-09-30 は30%。1万円未満で少額特例の対象の会社なら `少額特例`（少額特例は 2023-10-01〜2029-09-30 の取引だけ。期間も設定ファイルから読む）。2023-09-30 以前の取引は登録番号に関係なく `制度前`
- 要確認に回す条件を足す：軽減税率の可能性（飲食料品・新聞）、証憑に登録番号が無い課税仕入、税区分が科目の既定と違う行、証憑の税率と税区分の税率が違う行。証憑の税率と合わない承認済みの行（自動承認を含む）は承認を外して要確認に戻す。確立済みパターンでも、証憑の税率が8%・混在で税区分と合わない行、軽減税率の可能性がある科目でパターンに税区分が無い行は自動承認しない
- 固定資産の科目の既定税区分（課税仕入）は借方（取得）だけに入れる。売却は売却価額を貸方の課税売上10%で人が付ける
- 確認用Excelに税区分・インボイスの列を出す（見るだけ。Excelで書き換えても反映しない。直すのは `set-accounts`〈承認前〉・`set-tax`〈登録済み〉・`split-tax`〈税率の混在〉。出力後に税の列が変わった行は承認しない）

### 3.5 検算（check.py）に足す項目

課税の年度だけ：
- PL科目の行に税区分が空のものが無い
- 税区分が科目の区分と矛盾しない（費用科目に「課税売上」等）
- 課税仕入なのにインボイスが空の行が無い（インボイス必須は原則課税のときだけ。簡易課税・2割特例では空でよい）。個別対応方式なのに個別対応が空の行が無い
- 証憑（1つに決まったもの）の税率と税区分の税率が合う（8%なのに10%・10%なのに8%軽・混在なのに税率ごとの行に分けていない、はNG）
- 警告：経過XX・制度前・少額特例が取引日と合わない、資産・負債・純資産の科目の貸方に課税仕入、固定資産以外の資産・負債・純資産の科目に対象外以外の税区分

### 3.6 消費税の集計表

`tax-summary` コマンドで `output/consumption-tax-summary.csv`（とExcel）を作る。税区分×税率×インボイス×個別対応ごとに、税込額・税抜額・消費税額（国税7.8%／6.24%と地方税の内訳）を出す。

- 割戻し：区分ごとの税込合計から計算（10%：税込×10/110）。端数は切り捨て
- 積上げ：仕入は行ごとに計算して合計する（売上の積上げは請求書ごとの税額が要るので段階3では扱わず、`calc: 積上げ` の年度は売上だけ割戻しで計算し、その旨を集計表に書く）
- 経過措置の行は、税額に割合を掛けた控除対象額も出す
- この集計表がXML（§6.5）と、未払消費税の見積もり（§4.1-6）の元になる

## 4. 3b：決算整理（kessan-close）

スキル `.claude/skills/kessan-close/SKILL.md` と、コマンド群を作る。全体設計 §8 のチェックリストを順に処理し、各項目の結果は仕訳候補として staging に出し、承認後に adjustments.csv（伝票番号 `A1`…）へ登録する。**検算にNGが1つでもあれば実行を拒否する**（全体設計どおり）。

### 4.1 チェックリスト

1. **未払・未収**
   - 未払候補（evidence.csv の `状態=未払候補`）と、翌期首の明細の振込を、取引先・金額・支払期日で照合する。突き合わせの窓は「支払期日の前後10日、支払期日が無ければ期末から3か月」（宿題：突き合わせ窓の拡大）
   - 翌期の明細は「翌期の年度フォルダの staging/journal」か、翌期の明細を `inbox/` に置いて読み取ったもの（期間外として登録はしない）から探す
   - 期末日までの役務・請求で期末後に払ったものを「未払金／未払費用」の候補に、期末後に入金された当期分の売上を「売掛金」の候補にする
2. **前払**：年払いの保険料・サブスク（摘要・取引先のパターンと金額）を前払費用の候補にし、月割りで当期分と翌期分に分ける
3. **減価償却**：`context/company/fixed-assets.csv`（台帳）から、定額法・定率法・一括償却資産（3年均等）・少額減価償却資産の特例（即時償却）で当期の償却費を計算する。当期の10万円以上の支出で台帳に無いものを、資産計上の候補に挙げる（特例を使うかはオーナーが決める）。耐用年数・償却率はコードに書かず `config/depreciation/` の表から読む（根拠URL・確認日付き）
4. **役員報酬**：月ごとの額が同額か確認し、違う月があれば指摘する（仕訳は作らない）
5. **現金・仮払金・役員借入金**：現金のマイナス、仮払金の残、役員借入金・貸付金の不自然な増減を要確認に挙げる（仕訳は作らない）。役員貸付金があれば認定利息の要否を挙げる（`monthly-closing-checklist.md` 項目15）
6. **消費税（課税の年度）**：§3.6 の集計表から納付税額を見積もり、`租税公課／未払消費税等` の候補を作る。中間納付があれば差し引く。**最終の税額は達人の計算結果で置き換える**（`set-tax` で上書きできるようにする）
7. **法人税等**：段階3では見積もらない。`法人税、住民税及び事業税／未払法人税等` の金額は、達人で計算した額をオーナーから受け取って `set-tax` で入れる（段階4で試算に置き換える）

### 4.2 宿題の解消（2026-09-17 時点の積み残し）

- **未払候補と後日の振込の照合**：§4.1-1
- **check.py の証憑照合**：evidence.csv にあって journal に対応する行が無い証憑（状態が「複数候補」「未払候補」のまま、または取り込み元IDの行が journal に無い）を検算の警告に出す。決算整理の前に必ず0件にする（未払候補は 4.1-1 で解消する）
- **複数候補・未払候補を解決するコマンド**：`resolve-evidence --evidence-id <ID> --match <明細の取り込み元ID>`（複数候補から1つに決める）、`--as-payable`（未払として決算整理へ回す）、`--as-new`（明細と対応しない新規仕訳にする）
- **「取引先名が摘要に無い」がカナ／漢字差で多発する件**：照合の前に、取引先名を法人格の略語（`company-name-abbreviations.md`）で読み替え、全角半角・カナの大小・長音を揃えた「読みの正規形」で比べる。漢字の取引先名には、確定した対応（漢字名⇔振込名義のカナ）を `context/company/kessan-payees.yaml` に貯め、2回目からは自動で当てる（新しい対応はオーナーの承認後に追加）
- **会社別の科目追加ファイル**：`context/company/kessan-accounts.yaml` で、汎用マスタに無い科目（区分・正常残高・表示区分・既定税区分）を足せるようにする。マスタと同名の科目は定義できない（エラー）

## 5. 決算書（3c）

### 5.1 作るもの（`output/` に出す）

- 貸借対照表・損益計算書・株主資本等変動計算書（Excel。1ファイルに3シート）
- 個別注記表の雛形（重要な会計方針：減価償却の方法、消費税の会計処理＝税込方式 など、帳簿から決まるものだけを埋めた文案。最終はオーナーが直す）
- 内訳書の材料（科目・補助科目ごとの期末残高。預貯金・売掛金・買掛金・借入金・役員報酬手当等など）
- 概況書の材料（主要科目と、月別の売上・仕入・人件費・源泉所得税）

PDF は段階3では作らない（Excelで確認し、印刷・電子申告は達人側で行う）。

### 5.2 集計

- 試算表（journal＋adjustments＋期首残高）から、科目マスタの `表示区分` で区分して並べる。科目の並び順は科目マスタの順
- 段階利益（売上総利益・営業利益・経常利益・税引前当期純利益・当期純利益）はスクリプトで計算する
- 株主資本等変動計算書：資本金・資本剰余金・利益剰余金（繰越利益剰余金）ごとに、前期末残高（期首残高）・当期変動（当期純利益、配当等の仕訳）・当期末残高
- 決算書の数字は、貸借一致（資産＝負債＋純資産）と、PLの当期純利益＝変動計算書の当期純利益を検算してから出す。合わなければ出さずにエラー

## 6. 達人用XML（3c）

`export-tatsujin --year-dir <Y> --kind {kessan,uchiwake,gaikyo,shohizei}`（省略時は該当する全部）で `output/tatsujin/` に出す。形式は `tatsujin-import.md` §3.5 の実物に合わせる。

### 6.1 共通

- 文字コード Shift_JIS（cp932）。cp932で表せない文字があれば出さずにエラー（どの科目・取引先かを示す）
- `SYSTEM`：`GYOUMUPREFIX`（決算書 HJ21／内訳書 UG13／概況書 UG16／消費税 SY35）、`VERSION` 1、`FUNCTIONID`（3／1／2／1）、`CONNECTEDPROGRAMVER`・`PROGRAMVER` は `1.0.0`、`PROGRAMNAME` は `kessan`
- `BASIC`：`KOMONSAKINAME` に会社名（`overview.md` から）、`JIGYOUNENDOFROM`／`TO` に期首日・期末日（YYYYMMDD）
- 金額は円の整数。0・該当なしは空要素（実物どおり）

### 6.2 決算書（HJ21）

- MFの実物の形（`Label`＋`Amount` 属性、区分の下に `<Item Label="科目名">金額</Item>`、経常利益は `OrdinaryIncome`）に合わせる。区分合計も書く
- 科目マスタの `表示区分` → XMLの区分要素の対応表をコードに持つ（流動資産→CurrentAssets、有形固定資産→PropertyPlantAndEquipment、販売費及び一般管理費→SellingGeneralAndAdministrativeExpenses …）
- 減価償却累計額は、達人側の「決算書の設定」で間接法／直接法を選ぶ前提で、科目として `Item` に出す
- `BASIC/PATTERN` はMFの実物の値（A2・B5・C2・D5・E1・F3・G1）を既定にして、`period.yaml` で変えられるようにする（各コードの意味は実機で確認：§9）
- `StatementChangesNetAssets` は §5.2 の変動計算書から作る

### 6.3 内訳書（UG13）

- 科目ごとに `KANJYOKAMOKU`（`Count` は1からの通し番号、`KANJYOKAMOKU_CODE` は科目マスタの行番号から作る一意の数字、`NAME`、`ZANDAKA`）、その下に補助科目ごとの `HOJYOKAMOKU`
- 補助科目は帳簿の補助（口座・取引先）。補助が空の行は補助なしとして科目の残高にだけ含める
- 期末残高は正常残高側をプラス（実物どおり、逆残高はマイナス）。BS・PLの全科目を出す（振り分けは達人が行う）

### 6.4 概況書（UG16）

- `SYUYOUKAMOKU` の各要素を、科目マスタに足す `概況書項目` 列（売上高→URIAGE_SYUUNYUUDAKA、役員報酬→YAKUINHOUSYUU …）で集計する。対応の無い要素は空
- `TUKIBETUURIAGEDAKA` は期首月から12か月（`_01`〜`_12`）。月別の売上・仕入・外注費・人件費・源泉徴収税額を journal から集計する

### 6.5 消費税（SY35、課税の年度だけ）

- §3.6 の集計表から、`D020114`（売上10%）・`D020113`（売上8%軽）・`D020124`／`D020123`（仕入10%／8%軽）・`D020134`／`D020133`（貸倒10%／8%軽）の各要素を埋める。旧税率の区分（`D020110`〜`D020112` 等）・特定課税仕入・輸入の要素は空で出す
- 割戻しは `_WARIMODOSHI`、積上げは `_TSUMIAGE` の要素に入れる。課税仕入の `KAZEI`（課税対応）／`HIKAZEI`（非課税対応）／`KYOTUU`（共通）は個別対応区分から、全額控除・一括比例配分のときは `KAZEI` に入れる。経過措置は `_INVOICEIGAI_WARIMODOSHI80`／`50` に入れる。**実物のSY35には70%・30%の要素が無い**（MFのガイドにも「消費税の達人は経過措置70%控除に未対応」とある）。経過70・経過30の行があるときは、XMLはそれ以外を埋めて出し、70%・30%分は集計表に別に出して「達人に手で入れる」と警告する
- `BASIC` に `HOUJINKOJINKUBUN` 1（法人）、`KAZEIKUBUN`（原則＝1、ほかは実機で確認）、`KEIKASHOCHIKAZEISHISAN`（実物は2）
- **簡易課税・2割特例の年度は、段階3ではXMLを出さない**（実物が原則課税の会社のものしか無く、事業区分の入れ方が不明なため）。集計表だけ出し、達人に手で入れる

## 7. エラー時の扱い

- 検算NG：`kessan-close` と `export-tatsujin` を拒否し、NGの一覧を出す
- 決算書の貸借不一致・当期純利益の不一致：出力せずエラー
- cp932で表せない文字：該当箇所を示してエラー（勝手に置き換えない）
- 税率・耐用年数の表に該当年度の値が無い：計算せずに停止（推測値を使わない）
- 例外は握りつぶさず、スキル側でそのまま報告する（`automation.md`）

## 10. 設計で決めたこと（私の判断。オーナーの確認待ち）

1. 段階3を 3a（課税対応の帳簿）→3b（決算整理・宿題）→3c（決算書・XML）の順に分けた
2. 消費税は**税込経理**だけを扱う（税抜経理・仮払／仮受消費税の科目は扱わない）。金額は税込のまま帳簿に持ち、税額は集計時に計算する
3. 旧税率・輸入・特定課税仕入・売上の積上げ計算は扱わない
4. 簡易課税・2割特例は、集計表は出すがXMLは出さない
5. 法人税等の金額は段階3では計算せず、達人の計算結果を入れる（試算は段階4）
6. 決算書はExcelだけで、PDFは作らない
7. 決算書XMLはMFの形（区分合計あり、`OrdinaryIncome`）に合わせ、`PROGRAMNAME` は `kessan` にする
8. 消費税の設定は年度フォルダの `period.yaml` に持つ
9. 未払の突き合わせ窓は「支払期日±10日、期日なしは期末から3か月」
10. インボイスの経過措置（80／70／50／30%）は設定ファイルで持ち、SY35に欄の無い70%・30%は集計表に出して手入力にする
11. 令和8年度改正の「同一の免税事業者等からの仕入れが年1億円超の部分は経過措置の対象外」は、対象のマイクロ法人では起こりにくいので扱わない
12. 2割特例の概算納付税額は、S − floor(S × 80%) − 貸倒の税額。S は売上の消費税額 − 売上返還の税額 + 貸倒回収の税額（特別控除は貸倒を引く前の売上の税額の80%、端数切り捨て）
