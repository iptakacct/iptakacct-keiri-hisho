# 会計システムなしで決算・法人申告データを作る仕組み 設計書

- 作成日：2026-09-16
- ステータス：設計承認済み（実装計画は未作成）

## 1. 目的

会計システム（マネーフォワード・freee等）を使っていない法人について、クライアントから受け取った資料（口座明細・領収書等）だけで帳簿を作り、決算書と法人税等の申告に必要な数字を作成し、申告ソフト（達人シリーズ）に引き渡せるようにする。

## 2. スコープ

### 対象
- **マイクロ法人・消費税免税事業者**（一人社長・資産管理会社等。取引は年数百件まで、口座1〜2本、在庫なし）
- 受け取る資料：銀行・カードのCSV、通帳・明細のPDF/画像、領収書・請求書のPDF/画像、Excelの集計表・メモ（前期決算書・申告書を含む）
- 成果物：帳簿（仕訳帳・総勘定元帳・試算表）、決算書、勘定科目内訳明細書の材料、達人への引き渡し資料

### 対象外（今回は作らない）
- 申告書（別表・地方税・消費税申告書）そのものの作成：達人で行う
- 電子申告（e-Tax/eLTAX）の送信：達人・オーナーが行う
- 消費税の課税事業者、棚卸資産のある法人：後続の拡張で対応（列・処理を追加する前提で設計する）

### 前提となる責任分担
- **AI**：資料の読み取り、仕訳科目の判断、不明点の洗い出し
- **スクリプト**：集計・残高・減価償却・税額試算など、数字の確定はすべてスクリプトで行う（AIが暗算で数字を作らない）
- **人（オーナー＝税理士）**：取り込み候補の承認、決算上の判断（特例の適用可否等）、達人での最終確認と申告

## 3. 全体の流れ

```
①資料受領 → ②読み取り・仕訳候補化 → ③人の確認 → ④帳簿CSVへ登録
  → ⑤検算（貸借・口座残高・重複） ── NGなら⑥以降に進まない
  → ⑥決算整理（未払/前払・減価償却・法人税等）
  → ⑦決算書・別表転記用数値 → ⑧達人へ引き渡し → ⑨オーナーが最終確認・申告
```

## 5. データ形式

### journal.csv / adjustments.csv
1行＝仕訳1行。複合仕訳は同じ伝票番号で複数行。

| 列 | 内容 |
|---|---|
| 伝票番号 | 事業年度内で一意。journal.csv は数字の連番（1, 2…）、adjustments.csv は「A」で始まる番号（A1, A2…）とし、両ファイルで同じ番号を使わない（検算「伝票番号」で確認） |
| 日付 | YYYY-MM-DD |
| 借方科目 / 借方補助 | 科目は accounts-master.csv に存在するもののみ（スクリプトで検証） |
| 貸方科目 / 貸方補助 | 同上 |
| 借方金額 / 貸方金額 | 円・整数。複合仕訳では片側だけの行がある（例：借方 役員報酬 300,000 ／ 貸方 普通預金 280,000 と 預り金 20,000 を3行で）。伝票ごとに借方合計＝貸方合計 |
| 摘要 | |
| 取引先 | |
| 証憑ファイル | inbox/ からの相対パス |
| 取り込み元ID | ファイル名＋行番号、または明細（日付・金額・摘要・口座）のハッシュ。決算整理仕訳は空 |
| 登録区分 | 自動（確立済みパターン）／確認済／決算整理 |
| 登録日時 | ISO 8601 |

- 消費税関連の列は持たない（課税事業者対応時に追加する）。
- **同一の取り込み元IDの行は登録できない**（スクリプトで拒否）。

### staging.csv
journal.csv の列に加え、`読み取り信頼度（高/低）`・`判定（確立済み/要確認）`・`要確認理由` を持つ。

### import-log.csv
`取り込み日時, ファイル名, 対象期間, 件数, 合計額（入金/出金）, 登録伝票番号の範囲`

## 6. 資料→帳簿（kessan-books）

1. 資料を `inbox/` に置き、スキルを実行する。
2. 形式別に処理する。
   - **CSV**：スクリプトで読み込み。銀行・カードごとの列の違いは `kessan-sources.yaml` の対応表で吸収する。対応表が無い形式は、AIが列を推定して対応表の追記案を出し、承認後に取り込む。
   - **PDF/画像**：AIが読み取り、staging.csv に出力する。通帳・明細は**ページごとに「前ページ繰越残高＋入金−出金＝ページ末残高」を検算**し、合わないページの行はすべて読み取り信頼度「低」とする。
   - **Excel**：AIが内容を見て資料の種類（出納帳・売上表・前期決算書等）を判定してから取り込む。前期決算書は期首残高の根拠として使う。
3. 取り込み前に `data-import.md` の手順で二重取り込みを確認する（import-log.csv の期間・合計額との照合、ファイル内重複、journal.csv との突合）。
4. AIが科目候補を付ける。判断材料はその会社の過去仕訳と `accounting-rules.md`。法人名の略語は `company-name-abbreviations.md` で読み替える。
5. 候補を「確立済みパターン」と「要確認」に分け、確認用Excel（`output/review-YYYYMMDD.xlsx`）とチャットで提示する。要確認とする条件：新規の取引先・摘要、読み取り信頼度「低」、略語の読み替えが曖昧、10万円以上の支出（固定資産の可能性）、役員との取引。
6. 承認された行だけ journal.csv に追記し、import-log.csv を記録する。確立済みパターンのうち accounting-rules.md に明記されているものは、承認なしで登録してよい（既存の「確立済みパターンのみ自動化」原則）。

## 7. 検算（check.py）

登録のたびに自動実行し、結果を `output/check-result.md` に出す。

1. 伝票ごとに借方合計＝貸方合計
2. 科目が accounts-master.csv に存在する
3. 預金科目の帳簿残高＝通帳・明細の残高（口座ごと・月末ごと。明細に残高がある場合）
4. 取り込み元IDの重複なし。同日・同額・同取引先の行は重複候補として警告
5. 正常残高方向と逆になっている科目・補助科目がない（月次締めチェックリスト項目6）
6. 期首残高＝前期決算書の期末残高

**1つでもNGがあれば kessan-close は実行を拒否する。** NGの一覧と該当伝票を報告する。

## 8. 決算整理（kessan-close）

チェックリスト形式で順に処理する。各項目の結果は仕訳候補として adjustments.csv の staging に出し、承認後に登録する。

1. **未払・未収・前払**：翌期首数か月の明細から当期分の支払・入金を候補化。年払いの保険料・サブスクは前払費用候補とする。
2. **減価償却**：`fixed-assets.csv` からスクリプトで計算。当期の10万円以上の支出から取得資産の候補を挙げ、台帳への登録を提案する。少額減価償却資産の特例などの適用可否はオーナーが判断する。
3. **役員報酬**：月額が定期同額か確認し、変動があれば指摘する。
4. **現金・仮払金・役員借入金**：現金のマイナス残高、仮払金の残存、役員借入金の不自然な増減を要確認に挙げる。
5. **法人税等**：`tax_calc.py` が税引前当期純利益から、法人税・地方法人税・住民税（法人税割・均等割）・事業税・特別法人事業税を試算し、未払法人税等の仕訳候補を作る。
   - 税率はコードに書かず `config/tax-rates/<年度>.yaml` から読む。地方税は `overview.md` の自治体コードで引く。**年度が変わるたびに、国税庁・各自治体の公表資料で確認してから更新する**（yamlに根拠URLと確認日を記載）。
   - 損金不算入項目（法人税等・交際費の限度超過・役員給与の否認分等）を別表4の加算候補として一覧にする。
   - **試算は検算用**。最終的な税額は達人の計算結果とし、差があれば原因を確認メモに記載する。

## 9. 出力（output/）

- 試算表・総勘定元帳・仕訳帳（Excel・PDF。電子帳簿保存の保存用を兼ねる）
- 決算書（貸借対照表・損益計算書・株主資本等変動計算書・個別注記表）
- 勘定科目内訳明細書の材料（預貯金・借入金・役員報酬手当等。内訳概況書の達人へ引き渡す）
- 達人への引き渡し資料
  - 取り込み用ファイル（法人税の達人（決算書作成機能）・内訳概況書の達人向け。形式は実装の最初に確認。確認できるまでは作らない）
  - 転記一覧（別表番号・欄・金額・根拠伝票番号）
- 確認メモ：判断した点・要確認事項・税額試算と達人の計算結果の差

## 10. エラー時の扱い

- 検算NG：⑥以降に進まない（前述）。
- 読み取り不能な資料：staging に入れず、ファイル名と理由を要確認として報告する。
- 税率yamlに当該年度・自治体の値が無い：税額試算を行わずに停止し、追加を依頼する（推測値を使わない）。
- スクリプトの例外：握りつぶさず、スキル側でエラー内容をそのまま報告する（`automation.md`）。

## 11. テスト

- **単体テスト**（pytest）：取り込み（CSV列対応・重複拒否）、check.py の各項目、集計（試算表・決算書）、減価償却、税額試算。
- **通しテスト**：架空のマイクロ法人1社・1年分のサンプル資料（CSV・通帳の画像・領収書）と、手計算で作った正解（決算書・税額）を `.claude/scripts/kessan/tests/fixtures/` に置き、最初から最後まで通して一致を確認する。実クライアント情報は含めない（leak-scan対象）。
- **実運用前**：実クライアントの初回は、既存のやり方と並行して作り、結果を突き合わせてから本番とする。

## 12. 実装の段階分け

それぞれ実装計画 → 実装 → 確認を終えてから次へ進む。

| 段階 | 内容 | 完了条件 |
|---|---|---|
| 0 | 達人（法人税の達人（決算書作成機能と別表）・内訳概況書の達人）の取り込み仕様の確認 | 取り込める項目と形式を `docs/` にメモし、引き渡しファイルを作るか転記一覧のみにするかを決める |
| 1 | 帳簿の基盤：データ形式・CSV取り込み・重複防止・check.py・試算表 | サンプルのCSVから試算表が出て、検算の全項目がテストで確認できる |
| 2 | 資料の読み取り：PDF/画像/Excelの読み取り・staging・確認の流れ（kessan-books） | サンプルの通帳画像・領収書から staging→承認→journal まで通る |
| 3 | 決算整理と決算書（kessan-close の⑥⑦、税額以外） | サンプルで決算書が正解と一致する |
| 4 | 税額試算と達人への引き渡し | サンプルで税額試算が正解と一致し、引き渡し資料が出る |

## 13. データの保管

- `work/kessan/` の帳簿CSV・出力はgitで管理する（既存の `work/` と同じくプライベートリポジトリへバックアップ）。
- `inbox/`（受領資料の原本。画像・PDFで容量が大きい）は `.gitignore` で除外し、原本の保管は別途行う。
