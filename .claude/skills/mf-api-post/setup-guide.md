# 新規会社のマネーフォワードAPI連携セットアップ手順

新しい会社をマネーフォワード クラウド会計のAPI直接連携に追加する際の、一回限りの手順。

## 事前準備（ブラウザでの操作）

1. `https://app-portal.moneyforward.com/`に、対象会社の全権管理者でアクセスし、アプリポータルを「利用開始」する（まだの場合）。画面左メニューの「ユーザー」で自分のユーザーを追加し、権限に「システム管理」「アプリ開発」の両方、および「クラウド会計・確定申告」のアプリ連携にチェックを入れて保存する。
2. アプリ開発画面の「新規登録」から新規アプリを作成する。
   - アプリ名称：例「keiri-hisho-<会社名>」
   - リダイレクトURI：`http://localhost:8765/callback`（このページは実在しなくてよい。ブラウザが「サイトにアクセスできません」と表示しても、アドレスバーのURLに`code`パラメータが載っていれば成功）
   - クライアント認証方式：**Basic**（このスキルの実装がBasic認証ヘッダー方式に対応しているため、必ずこちらを選ぶ）
3. 発行されたClient ID・Client Secretを、`companies.json`の対象会社エントリの`credentials_path`が指す場所に、以下の形式で保存する（このファイルは`.gitignore`の`credentials*`パターンで除外される）。

```json
{
  "client_id": "（ここに貼る）",
  "client_secret": "（ここに貼る）"
}
```

Client Secretはチャット上で必要以上に再表示しない。このファイルへの書き込みは、`credentials*`パターンのセキュリティhooksによりAIからは実行できない設計なので、**オーナー本人がテキストエディタで作成する**。メモ帳で保存する際、ファイル名欄にフルパスをそのまま貼り付けると`...credentials_....json.txt`のような1つの長いファイル名で保存されてしまう典型的な失敗があるので、保存後はファイル名を確認する。

## 認可（スクリプトでの操作）

4. `bash .claude/skills/mf-api-post/scripts/mf-authorize-start.sh <company_key>` を実行する（`company_key`は`companies.json`の`name`または`office_id`）。表示されたURLをブラウザで開き、**事業所選択で対象会社だけを選ぶ**（他社を選ぶとデータ混在の原因になる）。許可すると`http://localhost:8765/callback?code=...`へリダイレクトされ「サイトにアクセスできません」的な表示になるが、これは想定通り。**アドレスバーのURLから`code`パラメータの値だけをコピーする**（`&`より前まで）。
5. `bash .claude/skills/mf-api-post/scripts/mf-authorize-finish.sh <company_key> <認可コード>` を実行する。成功すると「認可成功：〇〇（office_id: …）のみで疎通確認できました。」と表示される。
   - 想定外の会社が混ざっているエラーが出た場合は、事業所選択をやり直す（手順4から再実行）。
   - `GET /offices`は接続中の1事業者を**単一のオブジェクト**で返し、事業者コードは`code`キーに入る（配列`{"offices": [...]}`や`id`キーではない）。`lib/mf_api.py`の`verify_single_office`がこの`code`を`companies.json`の`office_id`と照合する。形が違うエラーが出た場合は、実際のレスポンスを見ながら`verify_single_office`を実機に合わせて修正する。

## 2社目以降（アプリは使い回す）

**アプリポータルのアプリは1つあれば、他の事業者の認可にもそのまま使える**（認可は事業者単位で、認可画面の「事業者を選択」で選んだ会社のトークンが発行される。先に認可した会社のトークンには影響しない）。

1. `companies.json` に会社を追加する（`credentials_path` は会社ごとに別ファイル。トークンは会社ごとに分かれる）
2. 既存の会社の認証情報ファイルから `client_id` と `client_secret` の2項目だけを、新しい会社のファイルへ写す。AIは認証情報ファイルを読めない（hooksがブロックする）ので、オーナーが手元で行う
3. 手順4・5を会社ごとに行う
4. 最後に `mf-healthcheck.sh` で全社を確かめる（先に認可した会社が切れていないかも同時に分かる）

- 同意画面のアプリ名は最初に作ったアプリの名前のまま表示されるが問題ない
- 別のマネーフォワードIDアカウントに属する事業者を同じアプリで認可できるかは、アカウントとアプリポータルの組み合わせによる。通らなければそのアカウント側でアプリを1つ作る

## 完了後

6. `companies.json`にその会社のエントリが無ければ追加する（雛形は`companies.example.json`）。
7. `mf-healthcheck.sh`を1回手動実行し、正常終了することを確認してから、スケジューラーへの登録（週1回程度）を行う。失敗時は全体通知チャンネルへBot（Incoming Webhook）経由で通知される（`.claude/scripts/.env`の`GENERAL_SLACK_WEBHOOK_URL`が必要。`.claude/rules/automation.md`）。

## トークンの寿命

アクセストークン1時間・リフレッシュトークン540日。**リフレッシュトークンは使い捨て**（更新のたびに新しい値が発行され、古い値はその場で消える）。同じ認証情報を同時に使う処理が重なると後発は `invalid_grant` になるため、`lib/mf_api.py` は更新の前後だけ会社ごとのロックを取る（`lib/mf_lock.py`）。540日を過ぎる前に、ヘルスチェックを定期実行して更新し続ける。
