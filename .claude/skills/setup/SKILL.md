# 目的

このリポジトリは「AI経理秘書」の標準フォーマット（テンプレート）である。使い始める人に対し、上から順番に・1問ずつ質問し、回答をもとに各ファイルを埋めていく。

# 2つのモード

- **ルートで実行された場合（初回導入）**：`keiri-hisho/CLAUDE.md`の「基本設定」（オーナーの呼び名・秘書の名前・事務所名）と、`.claude/rules/communication.md`の署名を設定する。`.claude/scripts/.env`・`.claude/hooks/guard-allowlist.txt`・`config/mf-companies.json`が未作成なら、それぞれの雛形（`.env.example`等）から作るよう案内する（`.env`の値はオーナー本人が記入。AIは読まない）
- **クライアントフォルダで実行された場合（インスタンス設定）**：以下の質問リストに沿って進める

# 進め方の原則

- 質問は1つずつ。まとめて聞かない（回答が薄くなるため）
- 各質問への回答を得たら、対象ファイルをその場で更新し、内容を提示して確認を取ってから次の質問に進む
- 「未定」「わからない」と言われた項目は、無理に埋めず、該当ファイル内に「（未設定）」として残す
- **ヒアリングで深追いしない**：会計・業務の細部（自動仕訳のルール、消込対象の追加科目、小口現金・固定資産・在庫・月次フロー・銀行口座/カードの一覧、顧客の管理単位、`work/`のフォーマット、スキルの取捨選択など）は、`/setup`の場でまとめて聞き切ろうとしない。会計システムとの連携・実際の作業を通じて分かっていくものなので、デフォルト値のまま「（未設定・実務の中で判明次第追記）」として進めてよい

# ヒアリング文字起こしの取り込み

チャットで1問ずつ答えてもらう以外に、オンライン会議の自動文字起こしファイルをまとめて渡してもらう形でも進めてよい。

1. 対象フォルダ（`context/company/overview.md`に記載の「ヒアリング文字起こしフォルダ」）を確認する
2. ファイル名から、どの会社のヒアリングかを判断する。怪しい場合はオーナーに確認する
3. 内容を読み込み、質問リストの該当箇所に反映する
4. 処理済みファイルは「読込済」フォルダへ移す（ツールに移動機能が無い場合はコピーになるので、二重処理を避けるため処理前に「読込済」内の同名ファイルを確認する）

# 質問リスト（クライアントフォルダで実行時、上から順に）

## 0. 会社HPの確認

- 会社のホームページURLがあれば、質問1に入る前にWebFetchで内容を取得し、事業内容・代表者情報などを下書きとして抽出する。「HPからの下書き」として提示し、本人に確認・訂正してもらってから反映する（HPの記載は古い・誇張がありうるので鵜呑みにしない）

## 1. CLAUDE.md — 自己紹介・事業概要

- 会社名・屋号、事業内容、運営者・体制、この秘書に担わせたい役割
→ CLAUDE.mdの「自己紹介」「事業概要」に反映する

## 2. 文体・書式・機密のルール

共通ルール（ルートの`.claude/rules/`）を引き継ぐ。`/setup`の場では聞かない。このクライアントだけの例外は、実務の中で必要になったときにインスタンスの`.claude/rules/`に追記する。

## 3. context/company/overview.md — 事業概要（詳細版）

- 事業内容の詳細（サービス・商品のジャンル・形態）
- 対象Slackチャンネル：`/new-instance`でフォルダ名と同じチャンネルを作成済みなら、通常はそれをそのまま使う。1インスタンスで複数会社を扱う場合など自明でないケースのみ確認する
→ `context/company/overview.md`に反映する。「対象Slackチャンネル：#channel-a」のように明記し、`knowledge-collector`・`slack-digest`はここに書かれたチャンネルのみを対象にする

**経理BPOクライアント向け（核となる項目のみ）**
- 売上・費用の計上パターン（発生主義か現金主義か、よく使う科目・補助科目の使い分け）
- 売上の締め日・入金サイト、支払いの締め日・支払いサイト
- 使用している会計システム（freee・マネーフォワード等）とログインURL（ID・パスワードは聞かない）
→ `context/company/accounting-rules.md`に反映する

**会計システム別のセットアップ**
- freee：`freee-api-post`の`setup-guide.md`に従い、OAuthプライベートアプリ作成→`companies.json`へのエントリ追加→認可を行う。前提として、このインスタンス用の会計システムアカウントでこの会社が実際に見えるか確認し、見えなければ「ユーザー追加待ち」として記録し先に進まない
- マネーフォワード：`config/mf-companies.json`にこの会社のエントリを追加し、`mf-fee-post`の運用（`/mcp`で接続）に合流させる

**認証情報（値はAIに教えない）**
`context/company/credentials.md`に項目名だけの空テンプレートがある。実際のID・パスワードはオーナー・先方が直接このファイルを開いて記入する。チャットで伝えない（会話ログ・API送信という露出が発生するため）。AIは値の記入・読み取りを一切行わない。

**会計システム上でのアクセス確認**
claude-in-chromeでログイン済みブラウザセッションを開き、この会社のデータが表示されるか確認する。表示されない＝ユーザー追加されていない可能性が高く、この時点では作業できない。`accounting-rules.md`に「会計システムのユーザー追加待ち（要フォローアップ）」と記録し、無理に進めない。パスワードを使って自分でログインしようとしない。

## 4. context/customers/ — 顧客情報

`/setup`の場では聞かない。`context/customers/README.md`の共通方針（顧客＝売上計上先、個人情報も含めてこのフォルダで扱ってよい）に従い、実務の中で判明するたびに`context/customers/<顧客名>/overview.md`として追記していく。

## 5. work/ — 日々の運用

`/setup`の場では聞かない。基本フォーマットのまま使い始める。

## 6. .claude/skills/ — 使うスキルの選定

`/setup`の場では聞かない。既存スキル一式をそのまま使い始め、不要と分かったら削除、必要な追加スキルは`work/skill-backlog.md`に記録する。
