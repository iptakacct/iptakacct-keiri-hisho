# 目的

`keiri-hisho/テンプレート/`をコピーして、新しいクライアント用インスタンスを作る作業を自動化する。

# 進め方

1. クライアント名（フォルダ名）を確認する。まだ聞いていなければ1つだけ質問する
2. `keiri-hisho/` 直下で、`テンプレート/` を `<クライアント名>/` としてコピーする（`cp -r "テンプレート" "<クライアント名>"`）
   - スキル・エージェントはコピーしない：インスタンス用スキルとエージェントはルートの`.claude/`に共通で1本ずつあり、クライアントフォルダで起動しても親ディレクトリから読み込まれる。テンプレートに`.claude/skills/`・`.claude/agents/`が無いのが正常。新インスタンスの`.claude/skills/`に置くのは、その会社固有のスキルだけ
   - `テンプレート/`は常にテストデータの無いまっさらな状態を保つ。コピー後に個別のクリーンアップは不要
3. コピーしたフォルダを`git add`し、以下の形式でコミットする（確認は挟まず、そのまま実行してよい。git履歴に残るため、間違っていてもやり直しが効く）

   ```
   <クライアント名>/: テンプレート/からインスタンスを作成
   ```

4. ルートの`CLAUDE.md`「インスタンス一覧」に1行追記する
5. フォルダ名と同じ名前でSlackチャンネルを作成する（`slack_create_conversation`、`channel_name`にはフォルダ名をそのまま使う）。このクライアントの作業内容は、以降このチャンネルに投稿していく（`.claude/rules/output-format.md`参照）
6. 会計システムがマネーフォワード クラウド会計の場合、mfc_ca MCP（claude.aiカスタムコネクタ）の接続を案内する
   - このMCPは「1接続＝1事業者」で、接続先の切替にはオーナー本人が`/mcp`を操作する必要がある（AI側からは認証操作を開始できない）
   - 手順：`/mcp`→マネーフォワードMCP→（既に他社に繋がっていれば）「Clear authentication」→再度ツールを呼ぶタイミングで事業者選択画面が出るので、このクライアントの事業者を選んでもらう
   - 接続できたら`mfc_ca_currentOffice`で接続先の事業者名を確認し、想定のクライアントと一致するか確かめ、`config/mf-companies.json`にエントリを追加する
   - 会計システムがfreee等の場合はこのステップをスキップし、`/setup`の中で`freee-api-post`のセットアップに進む旨を伝える
7. 完了したら「`<クライアント名>/` を作成してコミットし、Slackチャンネル `#<クライアント名>` も作成しました。次は `/setup` でヒアリングに進めます」と報告する。`/setup`を続けて実行するかはオーナーの指示を待つ（自動では進めない）

# 注意

- クライアント名が日本語・スペース入りでもそのまま使ってよい
- `テンプレート/`自体にテストデータ・実データが紛れ込んでいないか気づいた場合は、コピー前に一言注意喚起する
