# 目的

複数のクライアント企業がそれぞれ別のSlackワークスペースを持っており、オーナーがそのすべてに目を通しきれず、自分宛メンションを見落とすことがある。このスキルは、オーナーがチャットで頼んだときに、指定ワークスペースでの未対応メンションを拾って報告する。

# 前提・できないこと

- Claude Code連携のSlackコネクタは**1ワークスペースしか同時接続できない**。カスタムコネクタでSlack公式のリモートMCPサーバーを追加接続しようとしても、既存コネクタと同一URL扱いで不可
- そのため、**このスキルは無人の自動定期実行ではなく、オーナーが都度チャットで依頼したときに動くオンデマンド専用**
- 自前でSlack App・MCPサーバーを外部ホスティングする案は、「クライアント情報を外部に出さない」方針と矛盾するため採用しない（クライアントのワークスペースにBotを常設し、ローカルのスクリプトから収集する方式は可）
- 結果はSlackには投稿せず、必ずその場のチャットで直接表示する

# 進め方

1. **対象ワークスペースを確認する。** メッセージから会社名・ワークスペース名が読み取れればそれを使う。曖昧な場合は1つだけ質問する
2. **現在接続中のSlackワークスペースを確認する。** 自分のユーザープロフィール取得ツール等でワークスペース名を確認する
3. **接続先が目的の会社と違う場合**、オーナーに次のように伝えて止まる：「今は〈現在のワークスペース〉に繋がっています。claude.aiの設定画面（設定→コネクタ→Slack）で〈目的のワークスペース〉に切り替えてから、教えてください」。切り替え完了の返事を待ってから再度ステップ2を確認する
4. **接続確認後、オーナー宛のメンションを検索する。** Slack検索系ツール（`slack_search_public_and_private`等）で、自分へのメンションを探す
5. **各メンションについて、そのスレッドでオーナー自身がまだ返信・リアクションしていないかを確認する。** 返信・リアクション済みのものは除外する
6. **判定基準：見落とし防止を優先する。** 明らかにFYI・お礼のみなど対応不要と確信できるもの以外は、判断が微妙でも「念のため」拾って報告する
7. **結果をチャットにそのまま表示する。** 件数が多い場合はワークスペース名・チャンネル名・投稿者・要旨・リンクを簡潔にまとめる。該当が無ければその旨を伝える

# 今後の追記予定

- 対象になりうるワークスペース名・会社名の対応は、各インスタンスの`context/company/`に一覧化して育てる
