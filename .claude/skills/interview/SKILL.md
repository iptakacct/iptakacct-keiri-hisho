# 目的

依頼の背景・目的・制約・完成条件を着手前に深掘りし、後で認識違いが起きないよう要求仕様メモ（spec）として残す。

# 手順

1. 依頼内容を確認し、以下を明らかにする質問を1〜3個する（聞きすぎない。すでに分かっている点は聞かない）。
   - **目的・背景**：なぜ必要か、何に困っているか
   - **完成条件**：何ができたら「終わり」か
   - **制約**：期限・予算・関わる人・避けたいこと
2. 回答を踏まえてspecを作成する。
3. `work/drafts/spec_YYYY-MM-DD_タイトル.md` として保存する。
4. 保存後、内容を見せて「この認識で進めていいか」を確認する。承認が得られてから着手する。

# 出力フォーマット

```
【要求仕様メモ】〇〇について

■ 目的・背景
- …

■ 完成条件
- …

■ 制約
- …

■ 進め方（案）
- …
```

# 注意

- 質問攻めにしない。すでに会話で分かっている内容を聞き返さない。

# Gotchas（過去の失敗メモ）
- （最初は空。失敗のたびに1行ずつ追記する）
