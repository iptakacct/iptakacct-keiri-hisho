# 新規会社のfreee API連携セットアップ手順

新しい会社をfreee API直接連携に追加する際の、一回限りの手順。

## 事前準備（ブラウザでの操作）

1. https://app.secure.freee.co.jp/developers/applications で、対象会社にアクセス権のあるfreeeアカウントでログインし、プライベートアプリを新規作成する。
   - アプリ名：例「keiri-hisho-<会社名>」
   - コールバックURL：`urn:ietf:wg:oauth:2.0:oob`
   - 権限設定：会計関連のデータ種別（`[会計]`が付くもの全て）について「参照」「更新」を付与する。画面下部で `[人事労務]` `[freee請求書]` 等の別カテゴリに切り替わるので、そこから先はチェックしない（経理BPO用途では会計カテゴリのみで十分）
   - 下書き保存でよい（公開申請不要）
   - **注意**：この画面でログインアカウントを切り替えたい時、「新しい法人事業所でログイン」ボタンは**既存アカウントへの切り替えではなく、新規の空の事業所をその場で作成してしまう**。ログインを切り替えたいだけなら、必ず「ログアウト」→ログイン画面から対象アカウントで再ログインする。誤って空の事業所を作ってしまった場合は、`アカウント設定 → 事業所管理 → 事業所情報 → 事業所の削除`から削除する（本人のパスワードが必要＝本人操作必須。作成者本人でも自己削除できずサポート問い合わせが必要になるケースがある）
2. 発行されたClient ID・Client Secretを、`companies.json`の対象会社エントリの`credentials_path`が指す場所に、以下の形式で保存する（`.gitignore`の`credentials*`パターンで除外される）。

```json
{
  "client_id": "（ここに貼る）",
  "client_secret": "（ここに貼る）"
}
```

Client Secretはチャット上で必要以上に再表示しない。
**注意**：このファイルへの書き込みは、`credentials*`パターンのセキュリティhooksによりAIからは実行できない（Read/Writeどちらも拒否される設計）。**オーナー本人がテキストエディタで作成する**。メモ帳で保存する際、ファイル名欄にフルパスをそのまま貼り付けると`...credentials_....json.txt`のような1つの長いファイル名で保存されてしまう典型的な失敗パターンがあるので、保存後は`ls`等でファイル名を確認する。

## 認可（スクリプトでの操作）

3. `bash .claude/skills/freee-api-post/scripts/freee-authorize-start.sh <company_key>` を実行する（`company_key`は`companies.json`の`name`または`company_id`）。表示されたURLをブラウザで開き、**事業所選択で対象会社だけを選ぶ**。表示された認可コードをコピーする。
   - `companies.json`の`company_id`が未確定（プレースホルダー）でも進めてよい。事業所選択画面へ遷移した直後のURL（`.../select_companies/<company_id>/authorization?...`）に実際のcompany_idが表れるので、そこで確定させて`companies.json`を更新できる
4. `bash .claude/skills/freee-api-post/scripts/freee-authorize-finish.sh <company_key> <認可コード>` を実行する。成功すると「認可成功：〇〇（company_id: …）のみで疎通確認できました。」と表示される。

**注意（重要）**：freeeのアクセストークンは**事業所単位ではなくアカウント単位**で発行される。手順3の「事業所選択」画面で1社だけを選んでも、発行されるトークンは**そのアカウントがアクセス権を持つ全事業所**に対して有効になる。そのため、認可に使うfreeeアカウントが対象会社以外の事業所にもアクセス権を持っていると、`verify_single_company`が「想定外の事業所が含まれています」で失敗する（事故防止のための意図した安全装置）。

- **事業所選択をやり直しても直らない**。根本対応は以下のいずれか：
  1. そのアカウントから、対象会社以外の事業所へのアクセス権を恒久的に外す（一時的に外して後で戻すと、次回のヘルスチェックで同じエラーが再発する）
  2. 会社ごとに完全に別のfreeeアカウントを使う
- 認可に使うアカウントを決める前に、`https://accounts.secure.freee.co.jp/`の事業所切り替えメニューで、そのアカウントがアクセス権を持つ事業所が対象会社1社だけになっているか事前に確認しておくと手戻りが少ない
- 他事業所へのアクセスを外す操作は、対象事業所側で管理者権限が無いと自分自身では行えない。管理者権限を持つ別アカウントから外してもらう
- `freee-authorize-finish.sh`は`verify_single_company`のチェックより前にトークンを保存済みなので、アクセス権整理が完了すれば、認可をやり直さなくても`freee-healthcheck.sh`を実行するだけで疎通確認が完了する

## 完了後

5. `companies.json`にその会社のエントリが無ければ追加する
6. `freee-healthcheck.sh`を1回手動実行し、正常終了することを確認してから、スケジューラーへの登録（週1回）を行う

## 「開発用テスト事業所」が消せない場合

freeeの開発者画面で作った「開発用テスト事業所」は、ユーザー自身では削除できない（freeeサポート回答：**紐づくアプリが0件かつ更新なしで3ヶ月経過すると自動削除**される）。それまで`GET /api/1/companies`に混ざり続け、疎通確認の単一事業所検証がNGになる。

対処：
1. 開発者画面（`https://app.secure.freee.co.jp/developers/applications`、事業所を「開発用テスト事業所」に切り替え）で、その事業所に紐づくアプリを全て削除する。**対象社側の連携用アプリは消さない**。事業所の切り替えでアプリ一覧の表示が変わるので、削除前に対象社側に連携用アプリが別に存在することを確認する
2. `companies.json`の該当エントリに`"ignored_company_ids": [<テスト事業所ID>]`を追加する。これでヘルスチェックはOKになる
3. 3ヶ月後、`freee-healthcheck.sh`実行時にそのIDが「実際」リストから消えたら、`ignored_company_ids`を外す
