# 目的

今日の作業を業務分野別に記録し、あとで `/weekly-report` が定点観測できる材料にする。

# 手順

1. 今日の日付（Asia/Tokyo）を確認する。
2. 今日やったことをオーナーに聞く（会話中にすでに話されている内容があれば、それも拾ってよい）。
3. 挙がった項目を、以下の分野タグに割り振る：経営／経理／財務／総務／バックオフィス／人事・採用／その他。該当が無い分野の見出しは作らない（存在しない実績を作らない）。
4. 各項目に**削減時間**を添える。「手作業なら何分／実際は何分／浮いた分数／発信ネタになるか」を**秘書が見積もる**（オーナーには聞かない）。
   - 手作業の分数は、同じ作業を人が画面で1件ずつ行った場合の現実的な時間で見積もる。盛らない。見積もれない項目（打ち合わせ・判断そのもの）は付けない
   - 実際の分数は、会話の記録で分かる範囲で書く（秘書の処理時間＋オーナーの確認時間）
   - 発信ネタは、症状→原因→対策の形で書ける失敗・制約の発見があれば「あり」とし、一言でネタ名を添える
   - ファイル末尾に、その日の合計（浮いた時間）を1行書く。月ごとに合計すると「AIで月〇時間浮いた」が出せる
5. `work/daily/YYYY-MM-DD.md` に出力フォーマットの形で書き込む。同日のファイルが既にあれば追記、無ければ新規作成する。
6. 書き込んだ内容を要約して見せる。

# 出力フォーマット

```
# 2026-07-22（水）

## 経理
- ○○社の未仕訳42件を登録
  （手作業なら約90分 → 実際は15分、75分浮いた ／ 発信ネタ：なし）
- △△社の取引先58件を一括修正
  （手作業なら約120分 → 実際は20分、100分浮いた ／ 発信ネタ：あり「APIの金額の罠」）

## 人事・採用
- …

浮いた時間の合計：175分
```

# 注意

- 分野分けに迷う項目は「その他」に入れてよい。無理に既存分野へこじつけない。
