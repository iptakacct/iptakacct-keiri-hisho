# 目的

この会社の月次数値を、会計ソフト（freee・MF等）のデータから月次サマリに仕上げる。1人で通しでやらず、4つの専門エージェントに分担させることで、数値の整合性チェックを省略しない。

（このAI秘書インスタンスは、経理BPOクライアント1社専属を想定している。複数クライアントを1インスタンスでまとめて扱う場合は、`context/customers/<クライアント名>/monthly/YYYY-MM.md` に読み替える。）

# 手順

1. 対象月を確認する。
2. 会計ソフト（freee・MF等）のエクスポートデータ、または月次の数値をオーナーから受け取る。無ければ「何がどの形式であればまとめられるか」を伝えて依頼する（無い数値を作らない）。
3. Agent Team を直列で起動する（Agent ツールで、前工程の出力を次工程の入力として渡す）。
   1. `monthly-data-collector` — 生データを構造化
   2. `monthly-classifier` — カテゴリ別に分類
   3. `monthly-summarizer` — 月次サマリを文章化
   4. `monthly-reviewer` — 通しで批判的にチェック（`context/company/accounting-rules.md`の自動仕訳起票のルール・消込確認対象科目・締め/入金/支払サイトも渡し、自動仕訳の誤起票や、売掛金等の発生〜消込漏れが無いか確認させる）
4. `monthly-reviewer` の指摘があれば、オーナーに見せた上で、必要なら該当工程からやり直す。
5. `monthly-reviewer` が「新しいルールが必要な項目」を挙げていれば、それぞれについて今後どう処理すべきかをオーナーに確認し、回答を新しい自動仕訳ルールとして `context/company/accounting-rules.md` に追記する（次回以降、同じパターンを自動処理できるようにするため）。
6. 最終版を `context/company/monthly/YYYY-MM.md` に保存する。

# 出力フォーマット

```
【月次まとめ｜2026年7月】

■ サマリ
- …

■ 前月比で大きく動いた項目
- …

■ レビュー結果（monthly-reviewerより）
- 指摘：… （無ければ「確認した上で指摘なし」）

■ 消込未了・サイト超過の疑いがある項目（あれば）
- …（科目・補助科目・部門・発生日・金額・想定サイトからの超過日数）

■ 新しいルールが必要な項目（あれば）
- …（処理方法をオーナーに確認し、確定後 context/company/accounting-rules.md に追記）
```

# 注意

- 数値の精度・粒度が月によって異なることがある。分からない項目は「不明」のまま出し、埋めない。
