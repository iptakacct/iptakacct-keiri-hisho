# kessan：会計システムなしで帳簿を作る

設計：`docs/superpowers/specs/2026-09-16-kessan-without-accounting-system-design.md`（全体）、`docs/superpowers/specs/2026-09-17-kessan-stage2-reading-design.md`（段階2：資料の読み取り・確認・承認）、`docs/superpowers/specs/2026-10-26-kessan-stage3-closing-design.md`（段階3：決算整理・消費税。§3 が消費税）

数字（集計・残高・検算・突き合わせ・二重防止）はすべてこのスクリプトで確定させる。AIは資料の読み取りと科目の判断だけを行い、暗算で数字を作らない。AIは `staging.csv`・`journal.csv`・`evidence.csv`・`import-log.csv`・`statement-balances.csv`・`discard-log.csv` を直接編集せず、必ずコマンドを通す。手順はスキル `.claude/skills/kessan-books/SKILL.md`。

## 準備

Python 3 と、次のライブラリを入れる。

```bash
pip install pyyaml openpyxl pytest
```

## 年度フォルダ（インスタンスの `work/kessan/<年度>/`）

| ファイル | 中身 |
|---|---|
| `period.yaml` | 事業年度の期首日・期末日（`init --start --end` で作成）。期間外の明細は取り込まず、期間外の日付は登録できない。課税の年度は `消費税:`（区分・方式・計算・控除・少額特例）も持つ（下の「消費税」節） |
| `inbox/` | 受領資料の原本（gitに入れない） |
| `extracted/` | AIが資料を読んで書いた読み取り結果（`<資料のファイル名>.json`。例：`通帳-2025-04.pdf.json`）。gitで管理する |
| `staging.csv` | 取り込んだ明細・仕訳候補。`承認` 列が `済` の行が `post` で登録される |
| `journal.csv` | 帳簿本体。直接編集しない（`post` 経由で登録する）。伝票番号は数字の連番 |
| `adjustments.csv` | 決算整理仕訳（段階3で使う）。伝票番号は `A1`, `A2`… と「A」で始め、journal.csv と同じ番号を使わない（検算「伝票番号」で確認） |
| `import-log.csv` | 取り込み記録。資料は年度フォルダからのパス（`inbox/…`、`/` 区切り）で記録する（銀行CSVも `inbox/` の中にあれば `inbox/2025-04.csv` の形。`inbox/` の外から取り込んだ銀行CSVだけはファイル名）。staging.csv の `証憑ファイル`・statement-balances.csv の `ファイル名` も同じ形。`口座ID` 欄は、銀行CSV・通帳は口座ID、出納帳は `出納帳:<科目>`、領収書・請求書は種類 |
| `statement-balances.csv` | 明細（CSV・通帳・出納帳）に載っていた残高（検算で帳簿と照合） |
| `evidence.csv` | 証憑（領収書・請求書）と明細行の対応。`状態` は 明細に対応／新規仕訳／複数候補／未払候補／破棄（`discard` で証憑から作った行を破棄した）。末尾の `支払期日`・`支払方法の推定`・`自信度` は読み取り結果の値（段階3の未払管理の材料） |
| `discard-log.csv` | `discard` で破棄した行の記録（日時・取り込み元ID・日付・金額・摘要・理由） |
| `opening-balances.csv` | 期首残高（前期決算書の期末残高。残高は正常残高側をプラスで書く。減価償却累計額もプラス） |
| `output/` | `check-result.md`（検算結果）、`trial-balance.csv`（試算表）、`review-YYYYMMDD.xlsx`（確認用Excel）、`set-accounts-YYYYMMDD.json`（AIの科目候補）、課税の年度は `consumption-tax-summary.csv`・`.xlsx`（消費税の集計表） |

インスタンスの `context/company/` には次を置く。

| ファイル | 中身 |
|---|---|
| `kessan-sources.yaml` | 口座・カード・現金と明細CSVの形式、`receipt_default`（領収書の既定の支払方法：`立替`／`現金`／空欄） |
| `kessan-accounts.yaml` | 会社別の追加科目（共通の科目マスタに無い科目を足す。マスタと同じ名前は足せない。追加科目はマスタの後ろに並ぶ。雛形は `テンプレート/context/company/kessan-accounts.yaml`） |
| `kessan-patterns.yaml` | 確立済みパターン（自動承認の根拠。オーナーの承認後に追加する）。課税の年度は、自動承認のときに相手側の空欄へ 税区分（パターン→科目の既定の順）・インボイス（パターン）を書く。課税仕入でインボイスが決まらない（原則課税のとき）、収益・費用なのに税区分が決まらない、行に入っている税区分がパターンの税区分と違う、会議費・交際費・福利厚生費・新聞図書費でパターンに税区分が無い（「軽減税率の可能性（パターンに税区分が無い）」）、証憑の税率が8%・10%で税区分の税率と違う／混在、のいずれかは承認せず、要確認理由（「確立済みパターンにインボイスが無い／税区分が無い／の税区分と違う」）を付ける（課税仕入のパターンには `インボイス` を書く） |
| `kessan-payees.yaml` | 支払先の対応表（漢字の取引先名⇔通帳・カードに出るカナの名義）。`add-payee` で足す（オーナーの承認後）。証憑の突き合わせ・確立済みパターン・決算整理の未払・未収の照合で使う |
| `kessan-prepaid.yaml` | 前払費用の登録簿（年払いの費用の名前・科目・摘要キーワードか取引先・月数）。月数は1〜12。キーワードと取引先を両方書いたら両方に一致した行だけが対象（AND）。オーナーの承認後に書く |
| `fixed-assets.csv` | 固定資産台帳（UTF-8 BOM付き）。列は 資産名・科目・取得日・事業供用日・取得価額・償却方法・耐用年数・前期末償却累計額・除却日・備考。償却方法は 定額法／定率法／一括償却／少額特例 |

## 手順

インスタンスフォルダで実行する（`<Y>` は `work/kessan/2026-03期` など）。

```bash
python ../.claude/scripts/kessan/cli.py init --year-dir <Y> --start 2025-04-01 --end 2026-03-31
# opening-balances.csv に期首残高を入れる
# context/company/kessan-sources.yaml に口座と明細形式を登録する
python ../.claude/scripts/kessan/cli.py inbox-status --year-dir <Y>          # 未処理の資料の一覧
python ../.claude/scripts/kessan/cli.py import-bank --year-dir <Y> --account-id <口座ID> --file <Y>/inbox/<明細>.csv
# AIが PDF・画像・Excel を読み、<Y>/extracted/<資料のファイル名>.json を書く
python ../.claude/scripts/kessan/cli.py import-extracted --year-dir <Y>      # extracted/*.json をすべて（--file で指定も可）
# AIが要確認の行の科目候補を <Y>/output/set-accounts-YYYYMMDD.json に書く
python ../.claude/scripts/kessan/cli.py set-accounts --year-dir <Y> --file <Y>/output/set-accounts-YYYYMMDD.json
python ../.claude/scripts/kessan/cli.py split-tax --year-dir <Y> --id <取り込み元ID> --part 10:1080 --part 8:540   # 課税の年度：税率が混在する明細を税率ごとに分ける
python ../.claude/scripts/kessan/cli.py review --year-dir <Y>                # 確認用Excel
python ../.claude/scripts/kessan/cli.py apply-review --year-dir <Y> --file <Y>/output/review-YYYYMMDD.xlsx
python ../.claude/scripts/kessan/cli.py approve --year-dir <Y> --review-file <Y>/output/review-YYYYMMDD.xlsx --numbers 1 2   # チャットで番号を挙げて承認されたとき
python ../.claude/scripts/kessan/cli.py approve --year-dir <Y> --ids <取り込み元ID> ...   # 行を取り込み元IDで特定して承認されたとき
python ../.claude/scripts/kessan/cli.py unimport --year-dir <Y> --source inbox/<資料> [inbox/<資料> ...]   # 読み違えた資料の取り込みを取り消す（期間が重なる資料は並べる）
python ../.claude/scripts/kessan/cli.py discard --year-dir <Y> --ids <取り込み元ID> ... --reason <理由>   # 確認済みの重複などを破棄
python ../.claude/scripts/kessan/cli.py post --year-dir <Y>                  # 登録＋検算
python ../.claude/scripts/kessan/cli.py check --year-dir <Y> --prev-year-dir <前期のY>
python ../.claude/scripts/kessan/cli.py tb --year-dir <Y>
python ../.claude/scripts/kessan/cli.py set-tax --year-dir <Y> --file <Y>/output/set-tax-YYYYMMDD.json [--prev-year-dir …]   # 課税の年度：登録済みの仕訳の税の列を直す
python ../.claude/scripts/kessan/cli.py tax-summary --year-dir <Y> [--prev-year-dir …]   # 課税の年度：消費税の集計表と概算納付税額
python ../.claude/scripts/kessan/cli.py resolve-evidence --year-dir <Y> --evidence-id <証憑ID> (--match <取り込み元ID> | --as-payable | --as-new)   # 複数候補・未払候補・明細に該当なしの証憑を決める
python ../.claude/scripts/kessan/cli.py add-payee --year-dir <Y> --name <取引先> --kana <名義>   # 支払先の対応を足す（オーナーの承認後）
python ../.claude/scripts/kessan/cli.py close-set-amount --year-dir <Y> --item 消費税|法人税等 --amount <達人で計算した額>
python ../.claude/scripts/kessan/cli.py close-candidates --year-dir <Y> [--next-year-dir <翌期のY>] [--prev-year-dir …]   # 決算整理の候補と所見
python ../.claude/scripts/kessan/cli.py close-approve --year-dir <Y> (--ids close:… | --all)
python ../.claude/scripts/kessan/cli.py close-unapprove --year-dir <Y> --ids close:…   # 承認を外す（登録前）
python ../.claude/scripts/kessan/cli.py close-reject --year-dir <Y> --ids close:… --reason <理由>
python ../.claude/scripts/kessan/cli.py close-unreject --year-dir <Y> --ids close:…   # 却下を取り消す
python ../.claude/scripts/kessan/cli.py close-post --year-dir <Y> [--prev-year-dir …]   # 承認済みの候補を adjustments.csv に登録＋検算
python ../.claude/scripts/kessan/cli.py close-unpost --year-dir <Y> --ids close:… [--prev-year-dir …]   # 登録済みの決算整理仕訳を取り消す＋検算
```

- `init` は課税の年度なら消費税の引数も渡す：`--consumption-tax 課税 --tax-method 原則 --tax-calc 割戻し --tax-allocation 全額控除 [--small-exemption]`（`--tax-method` は 原則／簡易／2割特例、`--tax-calc` は 割戻し／積上げ、`--tax-allocation` は 方式=原則のときだけ必須で 全額控除／個別対応／一括比例配分）。免税なら `--consumption-tax 免税` か引数なし（`period.yaml` に `消費税` が無ければ免税）。既にある年度フォルダに後から指定して、`period.yaml` の消費税だけを変えられる（帳簿は触らない）。
- `init` の `--start`（期首日）・`--end`（期末日）は必須。既にある年度フォルダに違う期間を指定するとエラーになる（年度フォルダの取り違え防止）。
- 明細は新しい順・古い順のどちらで出力されていてもよい（全行に残高があれば、残高の連続から判定して古い順に取り込む。残高が連続しない明細は行の欠落を疑ってエラーにする）。
- 書き込む前に staging.csv・statement-balances.csv・import-log.csv が書き込めるか確かめる。途中の書き込みで失敗したときは、どこまで書いたかを出して止まる。閉じてから同じコマンドを再実行すると、明細の行は二重に取り込まず、書けなかった残高の記録・取り込み記録を埋める。
- `import-bank`（と `import-extracted` の通帳・出納帳）は、追加が0件（全部が取り込み済み）でも処理したファイルを `import-log.csv` に1行記録する。`対象期間` は新しく追加した行だけでなく、事業年度内・金額0以外の全部の行の期間、`件数`・`入金合計`・`出金合計` は新しく追加した行の分。同じ記録名のファイルを再実行しても、記録は1行のまま増やさず、行が増えて期間が広がったときは `対象期間` だけを広げる（件数・合計は最初の記録のまま）。`unimport` の期間の重なりの確認で、取り込んだ資料が漏れないようにするため。
- 期間が重なる明細を同じ口座に取り込むと警告を出す（同じファイルの再実行では、そのファイル自身の記録は挙げない）。日付・金額が取り込み済みの行と一致する行は、`要確認理由` に「二重取り込みの疑い」と入る。
- 銀行CSV・通帳・出納帳の取り込みで新しく追加する支払（出金）の行は、`evidence.csv` に金額が同じで日付が前後7日以内の証憑が無いかも確認する。「新規仕訳」の証憑があれば `要確認理由` に「証憑から計上済みの仕訳と金額・日付が近い（二重計上の疑い）」、「未払候補」の証憑があれば「未払候補の証憑と金額が一致（支払の可能性）」を追記する（既存の理由は消さず「／」で連結）。「新規仕訳」の証憑から作った行（`receipt:`）が staging にあり未承認なら、その行にも「明細にも同額の支払がある（二重計上の疑い）」を追記する。どちらもAIの判断だけで承認・削除せず、オーナーに同一取引かどうかを確認する。
- 複合仕訳は、`staging.csv` の複数行に同じ `伝票番号`（例：`T1`）を入れる（日付は全行同じにする）。登録時に正式な連番に振り直す。
- 検算でNGが1件でもあれば、決算の工程に進まない。

## 読み取り結果の取り込み（import-extracted）

- 形式の誤り（必須項目の欠落、日付・金額が読めない、期間外の日付、未登録の口座ID・科目）があるファイルは丸ごと取り込まず、ファイル名と理由を出す（終了コード4。他のファイルは取り込む）。直して再実行する。
- **1回の実行の中では、渡した読み取り結果ファイルの順番によらず、通帳・出納帳（明細）を先に、領収書・請求書（証憑）を後に自動で並べ替えて処理する**（証憑を先に処理すると、まだ明細が無く突き合わせ候補が見つからないまま新しい仕訳を余分に作ってしまうため。各グループ内は渡した順序のまま）。ただし銀行CSVの取り込み（`import-bank`）は別コマンドで、この並べ替えの対象外なので、証憑より先に済ませておく。
- **通帳**：ページごとに「繰越残高＋入金−出金＝残高」を確かめ、ページ内・前のページとの間で合わないページの行は `読み取り信頼度=低`・`要確認理由=ページの残高が連続しない` で取り込む。取り込み元IDは銀行CSVと同じ作り方なので、同じ取引をCSVと通帳の両方で受け取っても二重に入らない。
- **出納帳**：JSONの `科目`・`補助` の明細として取り込む。その（科目, 補助）が `kessan-sources.yaml` の `accounts` に登録されていなければ形式エラー（登録が無いと、出納帳の行が証憑との突き合わせ・二重計上の検知の相手にならないため。現金なら `id: cash`・`科目: 現金` を登録する）。
- **領収書・請求書**：`kessan-sources.yaml` の口座・カード・現金の支払（貸方）の行（journal.csv・staging.csv）のうち、金額が同じで日付が証憑の前後7日以内（両端を含む）、まだ証憑が付いていない行と突き合わせる。
  - 1件：新しい仕訳は作らず `evidence.csv` に対応を記録。staging の行で相手科目が空なら科目候補・取引先を入れ、`要確認理由` に「証憑と一致」を追記する（既存の理由は消さない。外すのは「相手科目未設定」だけ）。証憑の取引先名が明細の摘要に無ければ「取引先名が摘要に無い（突き合わせ先を確認）」も追記する。journal.csv は書き換えない。
  - 複数：新しい仕訳は作らず、`evidence.csv` に 複数候補 として記録（確認用Excelの「突き合わせ先が複数」）。
  - なし：支払方法で新しい仕訳の候補を作る（取り込み元ID `receipt:<証憑ID>`、`要確認理由=明細に該当なし`）。立替→貸方 役員借入金、現金→貸方 現金、口座・カード→貸方は空（明細の取り込み漏れを確認）。**領収書**で不明→`receipt_default`（未設定なら貸方は空）。後払い→仕訳を作らず 未払候補。**請求書は不明でも `receipt_default` を適用せず、後払いと同じ「未払候補」にする**（銀行振込での支払と二重計上になりやすいため。`receipt_default` は領収書のみに適用する）。
  - 同じ資料ファイルの再取り込みは `import-log.csv` で止める（件数0）。証憑ID（日付・金額・取引先を正規化したもののハッシュ）が `evidence.csv` にある証憑でも、**「別の」資料ファイルから来たものは取り込みを止めず**、証憑IDに `-2`・`-3` …を付けて別扱いで取り込み、`要確認理由` に「証憑の重複の疑い」（既存の証憑IDを付記）を追記する。日付・金額だけが同じ別の証憑があるときも、突き合わせの結果によらず同様に付記する（理由を書ける行が無い複数候補・未払候補などは、`import-extracted` の出力に一覧で出す）。どちらも自動では削除・統合しないので、同一の証憑かどうかをオーナーに確認する。「元」になるのは先に処理された方（`import-extracted` はファイル名の順で処理し、通帳・出納帳のグループが領収書・請求書のグループより先）で、後から処理された方に「証憑の重複の疑い」が付く。
  - `staging.csv`・`evidence.csv` まで書いて `import-log.csv` の書き込みだけが失敗した場合、再実行は「再開」として扱い、突き合わせをやり直さず記録を埋め直すだけにする（自分自身を「別ファイルからの重複」と誤認して余分な証憑・仕訳を作らないため）。
- 取り込んだ資料は `import-log.csv` に記録し、同じ資料の再取り込みは件数0になる。`種類=読めない` のファイルは取り込まず、確認用Excelの「読めなかった資料」に載る。

## 確立済みパターンと承認

- `import-bank`・`import-extracted`・`set-accounts` の後、`kessan-patterns.yaml` に一致した明細行（取り込み元IDが `bank:` の行。パターンの `取引先` は明細の `摘要` とだけ照合し、AIが書ける staging の `取引先` 欄では一致させない）を `判定=確立済み`・`承認=済` にする。対象は、パターンに一致し、かつその行の `要確認理由` が空か「相手科目未設定」だけの行に限る（読み取り信頼度が低い行、それ以外の要確認理由（「疑い」「連続しない」等）が付いた行、証憑から作った行（`receipt:`）、複合仕訳は対象外）。AIの科目候補とパターンの科目が違う行は承認せず、要確認理由に書く。パターンの `摘要キーワード`・`取引先` は2文字未満だと登録できない（`load_patterns` がエラーにする。誤爆防止）。
- `set-accounts`：`{取り込み元ID: {借方科目, 借方補助, 貸方科目, 貸方補助, 取引先, 判定, 要確認理由}}` のJSONを検証してから反映する。科目マスタに無い科目、staging に無い行、承認済みの行、`判定=確立済み` の指定、明細側（口座・カード・現金）の科目の変更は、1件でもあれば何も反映しない。`要確認理由` は上書きせず既存の理由に追記する（スクリプトが付けた理由は消えない。借方・貸方の科目が両方埋まったときだけ「相手科目未設定」を外す）。
- `review`：確認用Excel。シート「確認」は未承認の行が上。二重計上・二重取り込み・証憑の重複の疑い、支払の可能性、取引先名が摘要に無い行は赤（最優先）、読み取り信頼度が低い行はオレンジ、明細に該当なしの行は黄色。各行に非表示の「確認用指紋」列を持たせる（`apply-review` が内容の変化を検知するために使う）。課税の年度は「貸方」の右に 借方税区分・貸方税区分・インボイス（借方・貸方のうち入っている方）の列を足す（免税の年度には出ない）。同じ取り込み元IDが複数行（`split-tax` で分けた複合仕訳）の指紋は、その行をまとめて1つにする。指紋の方式を変えたため、この変更より前に出した確認用Excelは全行が「変更あり」と判定され承認されない。`review` を出し直す。
- `apply-review`：Excelの `承認` 列が `済` で `修正メモ` が空の行だけを承認する（Excel側で科目・金額を書き換えても反映しない）。ただし、確認用Excel出力後に `set-accounts` 等で内容（日付・借方・貸方・金額・摘要・税の6列）が変わった行は、`承認=済` のままでも承認しない（「確認用指紋」列で検知し、変わった一覧を出す。`review` を出し直して確認する）。修正メモがある行は承認せず（承認済みなら承認を外して `判定=要確認` に戻す）、メモの一覧を出す。`承認` 欄に「済」以外（「OK」等）が書かれた行は承認せず件数を出す。Excelで「済」を消しても承認は外れない（外すのは修正メモ）。
- `approve --review-file <確認用Excel> --numbers N …`：チャットで番号を挙げて承認されたときに使う。確認用Excelで番号を取り込み元IDに置き換え、`apply-review` と同じ指紋の確認をする（Excel出力後に内容が変わった行は承認せず一覧に出す）。Excelに無い番号があれば何も変えない。
- `approve --ids …`：取り込み元IDを指定して承認する（指紋の確認は無い）。どちらも、借方・貸方の科目が埋まっていない行があれば何も変えない。

## 取り込みの取り消しと行の破棄

どちらも全部を検証してから書き（拒否する理由が1つでもあれば何も変えない）、承認済みの行・帳簿（journal.csv）に登録済みの行には触らない。

- `unimport --source inbox/<資料> [inbox/<資料> ...]`：資料の取り込みを取り消す。staging.csv のその資料の行、statement-balances.csv・import-log.csv の記録、evidence.csv の証憑を消す。`--source` には複数の資料を並べられ、全部を検証してからファイルごとに1回で書く。
  - 指定は記録どおりの名前（`inbox/…`）と完全に一致する資料だけを指す。ファイル名だけで記録された資料（`inbox/` の外から取り込んだ銀行CSVなど）も、そのファイル名と完全に一致すればその記録だけを指す（`--source 2025-04.csv inbox/2025-04.csv` で両方を取り消せる）。完全に一致する記録が無いフォルダなしの指定（例：`2025-04.csv`）は、ファイル名が同じ記録が1件だけならそれを指し、複数あれば（`inbox/2025-04.csv` と `inbox/現金/2025-04.csv` など）候補を挙げて何も変えずに止める。どれにも当てはまらないときは、ファイル名が同じ記録名を手がかりとしてエラーに出す。
  - 同じ口座（`import-log.csv` の `口座ID`。出納帳は `出納帳:…`）で期間が重なる、別の取り込み済み資料があるときは拒否する。資料の期間は `import-log.csv` の対象期間に、その資料の行（staging.csv・journal.csv・statement-balances.csv）の日付を合わせた範囲で見る（同じ取引の行はどちらか一方の資料の分として記録されているため、片方だけ取り消すと、もう片方の資料の行まで消える）。重なる資料もまとめて取り消す場合は `--source` に並べて指定する。領収書・請求書は対象外。
  - 明細に対応した証憑を取り消すときは、明細の行は消さず「証憑と一致」を外す。未承認で科目・補助・取引先が証憑のままなら空に戻して「相手科目未設定」を追記し、突き合わせの後に科目が変えられていたら戻さずに「証憑の取り消し後（科目を確認）」を追記する（確立済みパターンで自動承認されない）。
  - その資料や対応する明細行が承認済み・登録済みのとき、その資料の明細行に別の証憑が付いているとき（先にその証憑を取り消す）は拒否する。取り消した後は、読み取り結果を直して取り込み直せる。
- `discard --ids … --reason …`：未承認の行を取り込み元IDで破棄し、`discard-log.csv` に記録する。証憑から作った行（`receipt:`）の証憑は `evidence.csv` の状態を「破棄」にする。承認済み・登録済みの行、証憑が付いた明細行は拒否する。オーナーが重複などを確認してから使う。
  - 破棄した行は取り込み直しても入らない：`import-bank`・`import-extracted`（通帳・出納帳・領収書・請求書）は、取り込み元IDが `discard-log.csv` にある行を入れず、「破棄済みのため入れなかった行：N件」と表示する（`unimport` して取り込み直した場合も、同じ取引を含む別の資料を取り込んだ場合も同じ）。証憑は evidence.csv に状態「破棄」で記録し、仕訳の候補を作らない。破棄を取り消す手段はコマンドに無い（オーナーが `discard-log.csv` の記録を消した場合だけ、次の取り込みで入る）。

## Excel で CSV を扱うときの注意

- **`post`・`import-bank`・`import-extracted`・`set-accounts`・`apply-review`・`approve`・`unimport`・`discard` の前に、年度フォルダのCSVを Excel で開いていたら閉じる。** 開いたままだと書き込めず、エラーで止まる。確認用Excel（`review-YYYYMMDD.xlsx`）も、`review` を再実行する前に閉じる。
- 確認はできるだけ確認用Excelで行う（`staging.csv` を Excel で直接開かなくて済む）。
- Excel で `staging.csv` を保存するときは「CSV UTF-8（コンマ区切り）」を選ぶ。それ以外で保存すると文字コードが変わって読めなくなる。
- Excel で保存すると日付が `2025/4/1` 形式になることがある。`post` は `YYYY-MM-DD`（例：`2025-04-01`）以外の日付を受け付けないので、セルの表示形式を確認する。
- 金額に桁区切り（`1,000`）・円記号・全角数字が入っていても読めるが、マイナスの金額・金額が0の伝票は登録できない。

## 消費税（課税の年度）

課税事業者の年度だけ、仕訳に消費税の区分を持たせて集計表を作る。免税の年度（`period.yaml` に `消費税` が無い、または `区分: 免税`）では、税の列を埋めず、税の検算もしない。金額は税込のまま帳簿に持ち、税抜額・税額は集計のときに計算する（端数は切り捨て）。

- **`period.yaml` の `消費税`**：`区分`（免税／課税）、`方式`（原則／簡易／2割特例）、`計算`（割戻し／積上げ）、`控除`（方式=原則のとき：全額控除／個別対応／一括比例配分）、`少額特例`（true／false。税込1万円未満の課税仕入を少額特例にする。適用は設定ファイルの期間〈2023-10-01〜2029-09-30〉の取引だけ）。`init` の引数で書く。
- **段階3a より前に作った年度フォルダ**：`period.yaml` がある年度フォルダは、`init` 以外のコマンドの最初に税の列の無いCSVを今の列構成に直す（値と行の順序はそのまま）。
- **税の6列**（`staging.csv`・`journal.csv`・`adjustments.csv`）：`借方税区分`・`借方インボイス`・`借方個別対応`・`貸方税区分`・`貸方インボイス`・`貸方個別対応`。税区分は 課税売上10%／課税仕入10%／課税仕入8%軽／非課税売上／非課税仕入／対象外 など（`tax.py` の `TAX_CATEGORIES`）、インボイスは 適格／経過80／経過70／経過50／経過30／少額特例／なし／制度前（インボイス制度〈2023-10-01〉より前の取引。全額控除）、個別対応は 課税対応／非課税対応／共通（個別対応方式の課税仕入だけ）。
- **領収書・請求書の読み取り結果**には、任意で `税率`（`10`／`8`／`"混在"`）と `登録番号`（`T`＋13桁）を書く。`evidence.csv` に同名の列で残り、税区分とインボイスの自動補完に使う。
- **自動補完**（`tax_fill`）：`import-bank`・`import-extracted`・`set-accounts` の後、`review`・`apply-review`・`approve`・`post` の前に、未承認の行の空欄だけを埋める（手で入れた値は変えない）。収益・費用の科目と、固定資産の科目の借方（取得）は科目マスタ（`accounts-master.csv`）の既定税区分（固定資産の貸方〈売却〉には入れない）、証憑の税率が8なら 課税仕入8%軽 に、課税仕入のインボイスは制度前の日付なら 制度前、登録番号があれば 適格、無ければ日付に応じた経過措置（`config/consumption-tax/invoice-transition.yaml`）か なし（`少額特例` を使う会社は期間内の1万円未満が 少額特例）、個別対応方式なら 共通。補完できない・疑わしいものは `要確認理由` に書き、当てはまらなくなった理由（下の5つ）は外す。承認済みの行は、証憑の税率（8%・10%・混在）と税区分が合わないときだけ承認を外して要確認に戻す（税区分が科目の既定なら8%軽に直す。同じ取り込み元IDの行はまとめて外す）。
  - 「税率が複数（split-tax で分ける）」：証憑の税率が混在。`split-tax` で分ける（分けた伝票の行には付かない）。
  - 「証憑が無い課税仕入（インボイスを確認）」：インボイスを決める証憑が無い（原則課税のときだけ。簡易課税・2割特例はインボイスが要らない）。証憑を取り込むか、`set-accounts` でインボイスを入れる。
  - 「証憑に登録番号が無い（経過措置で計上。登録番号を確認）」：証憑に登録番号が無いので経過措置（またはなし）にした。登録番号が分かれば `set-accounts` で 適格 に直す（理由は外れる）。
  - 「証憑の税率（…%）と税区分（…）が違う」：証憑の税率と、手で入れた税区分の税率が合わない。
  - 「証憑の税率（8%）に合わせて税区分を8%軽に直したため承認を外した（確認して承認し直す）」：承認済みの行を直した。確認して承認し直す（この理由は自動では外れない）。
  - 「軽減税率の可能性（証憑で税率を確認）」：会議費・交際費・福利厚生費・新聞図書費で証憑に税率が無い。証憑を見て 10% か 8% か決める。
  - 「税区分が科目の既定（…）と違う」：入れた税区分が科目の既定と食い違う。意図したものか確認する。
- **`split-tax --id <取り込み元ID> --part 税率:税込金額 …`**：税率が混在する1枚の領収書を、税率ごとの行に分けた複合仕訳（`S1`, `S2`…）にする。明細側（口座・カード・現金）は1行のまま、相手側を分ける。合計が一致しないと何もしない。未承認で伝票番号の無い行だけ。承認はその後に行う。
- **`split-tax --voucher <伝票番号> --line <行> --part 税率:税込金額 …`**：登録済み（journal.csv）の伝票の1行を、税率ごとの複数行に分ける（`--id` とは同時に使えない）。分ける行は税区分に税率がある側（両側にあればエラー）。同じ伝票番号・登録日時・取り込み元IDのまま元の位置に入れる。課税の年度だけ。決算整理（adjustments.csv）の伝票は対象外。実行後に検算を流し、NGが残れば終了コード3。
- **`set-tax --file <JSON>`**：登録済み（`journal.csv`・`adjustments.csv`）の税の列だけを直す。`[{"伝票番号": "12", "行": 1, "借方税区分": "課税仕入8%軽"}]` の形（行は伝票内の1からの番号）。金額・科目は変えない。全件を検証してから反映し、直したあとに検算を走らせる（NGが残れば終了コード3）。承認前の行は `set-accounts` で直す。
- **`set-accounts` の税の列**：科目候補のJSONに上の6列も書ける。
- **検算**（課税の年度）：税区分が空・使えない値、課税仕入のインボイスの欠け（原則課税のときだけ）、個別対応の欠け、証憑（`evidence.csv` で1つに決まったもの）の税率と税区分の税率の食い違い（8%なのに10%、10%なのに8%軽、混在なのに税率ごとの行に分けていない）をNGにする。経過XX・制度前・少額特例が取引日と合わない、資産・負債・純資産の科目の貸方に課税仕入、固定資産以外の資産・負債・純資産の科目に対象外以外の税区分、は警告にする。
- **固定資産の売却**：売却価額（税込）を貸方の課税売上10%で計上する。帳簿価額との差は売却損益で、対象外にする。例（帳簿価額 500,000円の車両を 330,000円で売った）：
  - `普通預金 330,000 ／ 車両運搬具 330,000`（貸方税区分 課税売上10%）
  - `固定資産売却損 170,000 ／ 車両運搬具 170,000`（借方税区分 対象外）
  - 売却益が出るとき（帳簿価額 200,000円）は `普通預金 330,000 ／ 車両運搬具 200,000＋固定資産売却益 130,000` とし、貸方の2つとも 課税売上10%（合計が売却価額になる）
- **`tax-summary`**：検算にNGがあれば出さない。`output/consumption-tax-summary.csv`・`.xlsx` に、区分・税区分・インボイスごとの件数・税込・税抜・消費税額・国税・地方税・控除対象税額と、課税売上割合・概算納付税額を出す。返還・貸倒は自然な側（仕入返還は貸方、売上返還・貸倒は借方、貸倒回収は貸方）を＋、反対の側を−として集計する。方式による概算：原則は売上の税（返還を引き貸倒回収を足す）− 貸倒の税 − 控除対象税額（全額控除／個別対応／一括比例配分）、2割特例は 売上の税 − 切り捨て(売上の税×80%) − 貸倒の税、簡易は事業区分が要るため概算しない。`--prev-year-dir` を渡すと、前に走らせる検算に前期末との突き合わせも入る（`set-tax` も同じ）。
- **設定ファイル**（`config/consumption-tax/`、根拠URL・確認日つき。税率・割合はコードに書かない）：`rates.yaml`（10%・8%の国税／地方税の内訳）、`invoice-transition.yaml`（免税事業者等からの課税仕入れの経過措置の期間と割合、少額特例の期間）。
- 扱わないもの：旧税率（8%・5%・3%）、輸入、特定課税仕入、税抜経理、売上の積上げ（売上は割戻しで計算する）。

## 決算整理（kessan-close）

手順書は `.claude/skills/kessan-close/SKILL.md`。検算にNGがあれば `close-candidates`・`close-post` は実行を拒否する。流れは `check` → 証憑の未解決を `resolve-evidence` で片づける → `close-candidates` → オーナーに見せる → `close-set-amount`（消費税・法人税等）→ `close-approve` → `close-post`。

- 候補はすべて「要確認」で `adjustments-staging.csv`（伝票番号 C1…）に入り、`output/close-report.md` に項目ごとにまとめる。承認（`close-approve`）したものだけが `close-post` で `adjustments.csv` に `A1`, `A2`…（登録区分 決算整理）で入る。同じ取り込み元ID（`close:<項目>:<キー>`）が登録済みなら作り直さない。承認済みは内容が同じなら据え置き、再計算で内容が変わったら最新の内容に置き換えて承認を外す（古い額のまま登録しない）。未承認なら最新の内容で置き換え、もう出ない未承認の候補は消す。報告書の表は 借方・借方税区分・貸方・貸方税区分・金額 で、承認済み・登録済みの候補は staging・adjustments.csv に実際にある行を載せる（登録済みと再計算が違えば再計算の結果も並べる）
- 候補を1件だけ帳簿に足すとBS科目がマイナスになる・税区分が検算でNGになるものは staging に入れず所見にする。`close-post` は登録した後の帳簿を組み立ててマイナス残高・税区分の検算を先に流し、NGがあれば何も登録しない
- 項目の順：未払・未収 → 前払（と期首の戻し）→ 減価償却 → 役員報酬・残高の所見（候補なし）→ 消費税・法人税等
- 数字はすべてスクリプトが確定する。端数は円未満切り捨て。償却率は `config/depreciation/rates.yaml`（国税庁の別表。根拠URL・確認日つき）から読む
- **未払**：`evidence.csv` の未払候補の請求書（期末日以前）を、翌期の支払（`--next-year-dir` の staging・journal。期日の前後10日、期日が無ければ期末日の翌日から92日）と取引先・金額で照合して候補にする。**未収**は、翌期の入金（期末から60日以内）のうち当期の売上先と合うもの。期末の売掛金で説明できる入金は所見にする（登録済みの未収は数えない）。期首日より前の証憑・税率が混在する証憑（課税の年度。`resolve-evidence --as-new` → `split-tax`）は候補にせず所見。未収の貸方の税区分は、その取引先の当期の売上高の税区分が1つならそれ、決まらなければ 課税売上10%（所見）。翌期の伝票が 未払金／売掛金 の消込になっていなければ、登録後に直すよう要確認理由に書く（当期を先に登録してから翌期を直す。翌期を先に売掛金に直して未登録の未収の候補が出なくなったときは所見）
- **前払**：`kessan-prepaid.yaml` の登録簿に合う支払ごとに 金額 × 期末より後の月数 ÷ 月数 を前払費用に。月数は1〜12だけ（1年を超えるものは長期前払費用として手で扱う）。キーワードと取引先を両方書いたら両方に一致した行だけが対象（AND）。同じ取り込み元IDの行（1つの支払を分けた伝票）は登録簿の項目ごとに合計して1候補（1つの支払が2項目に分かれるときはキーを `取り込み元ID:名前` にする）。期首の前払費用は同じ名前の科目へ戻す候補
- **減価償却**：`fixed-assets.csv` から計算する。定額法・200%定率法は事業供用月から期末月まで（除却日があればその月まで）の月割り。**一括償却（10万円以上20万円未満）は 取得価額 × 月数 ÷ 36**（除却しても続く）。**少額特例（30万円未満、中小企業者等だけ）は事業供用した年度だけ**全額、年間上限は300万円 × 月数 ÷ 12。**12か月未満の事業年度では定額法・定率法は計算せず所見**にする。貸方は有形固定資産の定額法・定率法なら減価償却累計額、無形固定資産と一括償却・少額特例は資産の科目（直接控除）
- **消費税**（課税の年度）：年税額は `close-set-amount --item 消費税` の額（達人の計算結果）があればそれ、無ければ tax-summary の概算（同じ回の他の候補を含める）。**簡易課税は概算しないので上書きが必須**。仮払税金（補助なしか補助「消費税」）の期末残高を中間納付として差し引き、残りを未払消費税等（マイナスなら未収入金〈補助 消費税〉）にする。消費税の候補は、他のすべての候補を承認してからでないと登録できない（額が変わるため）。他の候補を `close-reject` で却下すると、承認済みの消費税の候補は承認が外れる（`close-candidates` を流し直す）。概算の候補は達人の額が出るまで承認しない（他の項目だけ先に登録する。`close-approve --all` は、消費税の額を `close-set-amount` で入れていなければ消費税の候補を承認せずに残し、その旨を出す。概算のまま承認するなら `--ids` で指定する）。`close-set-amount`（消費税・法人税等）の後に `close-candidates` を流し直していないその項目の候補（古い額のまま）は、`--all` でも `--ids` でも承認しない（要確認理由に「close-set-amount で額を入れたので close-candidates をやり直す」が付く）。概算を登録済みなら、`close-set-amount` と `close-candidates` では置き換わらない（所見が出るだけ）ので、`close-unpost --ids close:消費税:<期末日>` で消費税の伝票だけ取り消してから入れ直す（他の項目の伝票は残る）
- **法人税等**：見積もらない。`close-set-amount --item 法人税等` に入れた**期末の未払額**（年税額ではない）があるときだけ候補にする。仮払税金（補助「法人税等」）の中間納付があれば、借方 法人税等（未払額＋中間納付）／貸方 未払法人税等・仮払税金（法人税等）にして仮払税金も消す。マイナスの額は還付：借方 未収入金（補助 法人税等）還付額、貸方 仮払税金（法人税等）、差額（中間納付−還付額）を法人税等（マイナスなら貸方）
- `close-set-amount` の額は整数（還付はマイナス。消費税のマイナスは未収入金・雑収入の還付の候補）。額を入れ直すと、その項目の承認済みの候補は承認が外れる
- **承認の取り下げ**：`close-unapprove`（承認と判定を戻す。登録済みは不可）。staging.csv を手で編集しない
- **却下**：オーナーが拒む候補は `close-reject --reason`（理由は必須）。以後の `close-candidates` で出なくなり、報告書に理由つきで載る。`close-unreject` で却下を取り消すと次の `close-candidates` からまた出る（却下していないIDはエラー）。承認済みの候補が再計算で出なくなったときは承認が外れて所見が出る
- **登録の取り消し**：`close-unpost --ids close:…` で登録済みの決算整理仕訳を adjustments.csv から取り除く（`close:` の伝票だけ。他の伝票の番号は振り直さない）。先に各項目の後処理を戻し（未払の証憑は 未払候補・取り込み元IDは空に戻る）、1つでも失敗したら何も取り除かない。消費税の伝票が登録済みなら、他の項目の伝票は消費税と一緒に取り消す。取り消した後に検算を流し、NGが残れば終了コード3。取り消した候補は次の `close-candidates` で未承認の候補として出直す
- 上書き額と却下は `close-overrides.yaml` に保存する（直接編集しない）
- 登録後に `close-candidates` を流し直すと、登録済みの内容と再計算が違う候補は所見になる（直すなら `close-unpost` で取り消してから出し直す）。登録済みの消費税・法人税等の中間納付は、仮払税金の残高が0になっても足し戻して比べる
- 登録した後の混在税率の伝票は `split-tax --voucher <伝票番号> --line <行> --part 税率:税込金額 …` で分ける

## 決算書（段階3c）

```
python ../.claude/scripts/kessan/cli.py statements --year-dir <Y> [--prev-year-dir …]   # 決算書（Excel 3シート）と個別注記表の雛形
```

- 検算にNGがあれば出さない（終了コード1）。`output/financial-statements.xlsx`（貸借対照表・損益計算書・株主資本等変動計算書）と `output/notes-draft.md`（個別注記表の雛形。最終はオーナーが直す）を出す
- 科目マスタの表示区分で区分し、科目の並びはマスタの順。期末残高0の科目は出さない。減価償却累計額などの控除科目と逆残高はマイナスで出す
- 損益は繰越利益剰余金へ振り替えないので、貸借対照表の繰越利益剰余金は帳簿の期末残高＋当期純利益。変動計算書の変動は、当期純利益と、純資産の科目を動かした仕訳の摘要ごとの合計
- 貸借一致と、損益計算書の当期純利益＝変動計算書の当期純利益、変動計算書の期末残高の合計＝貸借対照表の純資産の部の合計を検算し、合わなければ何も出さない
- 変動計算書は摘要ごとに変動をまとめるので、純資産の仕訳（増資・配当など）は同じ内容なら同じ摘要で書く
- 決算整理の候補が残っている・法人税等が0・会社名が未設定のときは警告を出す（出力は止めない。法人税等は達人で計算した額を `close-set-amount` → `close-post` してから出し直す）
- 内訳書・概況書の材料も同時に出す（4つのファイルは全部書けたときだけ置き換える）
  - `output/uchiwake-material.xlsx`：全科目の期末残高と補助ごとの残高（シート「内訳書の科目」「全科目」。内訳書の種類は科目名からの目安）
  - `output/gaikyo-material.xlsx`：法人事業概況説明書の主要科目（シート「主要科目」）と、期首月からの月別の売上・仕入・外注費・人件費・源泉徴収税額（シート「月別」）。月は期末日の締め日で1か月ずつ区切る（20日締めの年度なら 3/21〜4/20 が1か月目で、概況書の月の欄は初日の月の 3。設立初年度の 6/15〜翌5/31 なら 6/15〜6/30 が1か月目で、あとは暦の月）。主要科目は科目マスタの「概況書項目」で集める

```
python ../.claude/scripts/kessan/cli.py export-tatsujin --year-dir <Y> [--kind kessan uchiwake gaikyo shohizei] [--prev-year-dir …]
```

- `output/tatsujin/<種類>-<GYOUMUPREFIX>-<期末日YYYYMMDD>.xml`（Shift_JIS・CRLF）に達人へ渡すXMLを出す。決算書 `kessan`（HJ21）・内訳書 `uchiwake`（UG13）・概況書 `gaikyo`（UG16）・消費税 `shohizei`（SY35）。省略すると4種類（消費税は下の条件）。数字は `statements` の材料と同じ集計から作る
- `SYSTEM/PROGRAMNAME` は `kessan`。顧問先名は `period.yaml` の `会社名`（`init --company-name <会社名>` で入れる。空なら警告して空で出す）
- 決算書の PATTERN（表示パターン）はMFの実物の値で固定。減価償却累計額は資産の部のマイナスの項目で出す
- 法人税等が未計上・決算整理の候補が残っていても出す（警告つき。達人で税額を計算するのに税引前の決算書が要る）
- 消費税XMLは**原則課税の年度だけ**。税抜額と税額の欄だけを埋める。経過80%・50%の税額は控除割合を掛ける前の額。積上げの年度の経過措置分は割戻しの欄に入れる。経過70%・30%は欄が無いので入れず警告（集計表から達人に手で入れる）。インボイスなしは控除0%なので入れない（手で入れるものも無い）。簡易課税・2割特例は出さない
- 集計の注意（課税売上高5億円超・課税売上割合95%未満なのに全額控除 など）も警告に出す。有価証券売却益・投資有価証券売却益に税区分「非課税売上」を付けた行があれば（他の税区分の行は対象外）、非課税売上の欄にそのまま入れたうえで、達人の有価証券の欄（譲渡対価の5%）で確かめるよう警告する
- `--kind` 省略で消費税XMLを出さない年度（免税・簡易・2割特例）に、以前に出した `shohizei-SY35-*.xml` が残っていれば「古いファイルが残っています。達人に渡さない」と警告する（消さない）
- 達人に渡す順番：⓪消費税以外の決算整理を登録する（消費税の概算の候補は承認せず残す。登録済みなら `close-unpost --ids close:消費税:<期末日>` で消費税だけ取り消す）①消費税（原則課税なら `--kind shohizei` を消費税の達人へ。簡易・2割は集計表から手入力）で年税額を出し `close-set-amount --item 消費税` → `close-candidates`・承認・`close-post` ②`statements` と `--kind kessan` を法人税の達人へ渡して法人税等を出し `close-set-amount --item 法人税等` → 同じく登録 ③`statements` と `export-tatsujin`（全部）を出し直し、内訳書・概況書を内訳概況書の達人へ
- 内訳書XMLの繰越利益剰余金は帳簿の期末残高（当期純利益を含まない）。補助の `Count` は科目ごとに1から
- cp932 で表せない文字が科目・補助・取引先にあると、何も書かずに止まる（どこの何の文字かを出す）
- 達人で読めるかの実機確認は `docs/kessan/tatsujin-import-test.md`

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常終了（`check`・`post` は検算NGなし） |
| 1 | エラーで止まった（入力の不備など。何も書いていない。ただし、`post` でメッセージに「登録は完了済み」とある場合は帳簿への登録は済んでいて後始末だけが失敗している。`import-bank`・`import-extracted`・`set-accounts` で「取り込みは完了しています」「科目候補の反映は完了しています」とある場合は、反映は済んでいて確立済みパターンの自動承認だけが止まっている（直して同じコマンドを再実行すると、二重には反映せず自動承認をやり直す）。取り込み・取り消しの途中の書き込みで止まった場合は、メッセージに更新済みのファイルが出る） |
| 2 | コマンドの使い方の誤り（必須の引数が無い等。argparse が出す） |
| 3 | `post`（と `set-tax`・登録済み伝票の `split-tax`・`close-post`・`close-unpost`）で登録（修正）は完了したが、検算でNGがある（`check-result.md` を確認） |
| 4 | `import-extracted` で形式エラーのファイルがあった（そのファイルは取り込んでいない。他のファイルは取り込み済み。自動承認も止まったときは、そのエラーも出したうえで 4） |

`check` は検算NGがあると 1 を返す。
