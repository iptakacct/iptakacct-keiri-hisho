# データ取り込みによる仕訳起票の二重取り込み防止（全クライアント共通）

CSV・Excel・API取得データなど、**外部データを取り込んで仕訳を起票する作業全般**（請求書受領システムのCSV、決済代行の精算データ、銀行明細のファイル取り込み、給与データ等、ツール・データ種別を問わない）に適用する。取り込むデータがファイル・期間の単位で二重になっていないか、同じものを2回取り込んでいないかを必ずチェックする。

## 取り込み前のチェック

1. **同じファイル・同じ期間を既に取り込んでいないか**：取り込み単位（ファイル名・対象期間・件数・合計額）を、過去の取り込み記録（各インスタンスの`work/`配下のログ）と照合する。同じ期間・同じ合計額の記録があれば取り込まない
2. **データ内の重複**：取り込むデータ自体に同一行（請求書番号・日付・金額・取引先が一致）が重複していないか確認する。ファイルの結合・再ダウンロードで同じ行が2回入っていることがある
3. **会計側との突合**：識別子（請求書番号・取引ID・摘要）で会計システムの既存仕訳を検索し、既に登録済みの行は除外する。識別子が無いデータは日付＋金額＋取引先で突合する

## 取り込み後

- 取り込み単位（日時・ファイル名・対象期間・件数・合計額・登録した仕訳番号の範囲）を`work/`のログに必ず残す。次回の1の照合材料になる
- 取り込み件数・合計額がデータ側と一致するかを確認してから完了とする

## 判断に迷ったら

同一と断定できない行（金額だけ一致、日付が近い等）は登録せず「要確認」に回す（`output-format.md`「確立済みパターンのみ自動化」と同じ安全側の原則）。二重計上は月次チェックリストの重複取引チェックでも拾うが、取り込み時点で防ぐのが本則。

## 証憑から手入力で立てる前に、請求書ルートで計上されていないか確認する（全クライアント共通）

決済代行（各種カード決済・コンビニ決済の代行業者等）の精算書は、売上がゼロの月や手数料が売上を上回る月に**マイナス（＝こちらへの請求）**になる。このとき手元の証憑を見て費用を手入力すると、**請求書取り込み（invox・freeeの証憑連携など）による計上と二重になる**。

**プラス（＝売上がある）なら、これまでどおり売上を計上する。**この節はマイナスの月だけの話。

1. **精算書がマイナスなら、まず請求書取り込み側に同じものが無いか探す**（会計側で請求書取り込み由来の仕訳〈MFなら`entered_by: JOURNAL_TYPE_BILLING`〉を、同月・同額で検索する）
2. **あれば何もしない。** 取り込みに任せる
3. **無ければ計上しない。**先方から手数料分の請求書が来たら対応すればよい。期ズレを気にして先に立てない。手元の証憑だけで費用を起こさない
4. **支払いの明細（総合振込バッチ等）は、費用科目ではなく未払金の消込で処理する。**費用科目で立てると、計上と支払いの二重計上になる

名義が他社のアカウント（グループ会社名義の決済口座など）でマイナスが出た場合も同じ。その会社が自社で先方へ払っているなら、こちらは請求書が来るまで何も計上しない。

見分け方：BS科目の補助科目がマイナスに積み上がっていたら、この形を疑う（`monthly-closing-checklist.md`項目6）。会社ごとの具体的な扱いは各インスタンスの`context/company/accounting-rules.md`に書く。

## 「重複」と報告する前に見る項目（全クライアント共通）

取引先・金額・日付が一致しただけで「重複」と報告しない。**同じ人・同じ額・同じ日の請求書が正しく2枚以上あるのは、珍しいことではない**。

1. **識別子を必ず並べる**：請求書番号・プロジェクト（部門）・件名・**取込日**。どれか1つでも違えば別の請求書である可能性が高い
2. **過去2〜3ヶ月の同じ組み合わせを見る**。同じ形（同じ人・同じ額・同じ日に複数枚）が既に承認・支払済みになっていれば、それがその会社の正しい運用。これが最も強い証拠になる
3. **計上日と請求日は別物**。どちらか一方だけで「同じ月の請求」と決めない
4. **ツール側の重複警告を根拠にしない**。請求書受領ツールの重複警告は「仕入先・請求日・金額」の3つだけで判定していることがあり、請求書番号もプロジェクトも見ていない。警告が付いているだけでは重複の根拠にならない
5. **逆に、取込日だけが違って他が全部一致するものは本物の二重取り込み**。同じ請求書を2回アップロードした形。この場合だけ削除候補として報告する
6. 相手のある取引（グループ会社間の入出金等）は、**相手方の帳簿で裏を取ってから**判断する（`monthly-closing-checklist.md`項目6）
7. **最後は証憑そのものを開いて対象期間を読む**。請求書なら「作業期間」「対象期間」欄（無ければ明細の「○月分」）が唯一の決め手になる。APIやシステムの項目（請求日・計上日）は人が手で直すので当てにならない。同じ人が毎月同額で請求している取引先では、この確認を省かない
   - ⚠️ **画像が潰れていたら読まない。**ブラウザ操作ツールのzoomは指定領域を切り抜くだけで拡大はしないので、狭い領域を指定するほど小さい画像になり、かえって読めなくなる。scaleを指定せずフル解像度でスクリーンショットを撮り、それでも読めなければPDFビューアの拡大ボタンで表示自体を大きくしてから撮り直す。**潰れた文字を推測で読んで判断しない**（実例：「6月分」を「8月分」と誤読し、重複でないものを2回続けて「重複」と報告した）

**なぜ**：ある会社の請求書受領ツールの承認待ちで「重複候補」として挙げた8組のうち7組が、実際にはプロジェクト別に分けて出された正規の複数枚請求だった（過去2ヶ月分の同じ組み合わせが既に承認・支払済みだった）。一方、取込日だけが違う2件は本物の二重取り込みだった。誤った重複報告は、正しい請求書の支払を止めてしまう。
