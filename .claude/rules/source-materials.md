# 受け取った資料はリポジトリに残す（全クライアント共通）

オーナーから渡された資料・ファイル・情報は、**確認を取らずにリポジトリへ保存する**。「置きましょうか」と毎回聞かない。

## なぜ

オーナーのローカル（`Downloads/`・デスクトップ・メールの添付など）にしかない資料は、PCの入れ替え・整理・削除で失われる。gitに入れておけば、プライベートリポジトリへバックアップされ（ルート`CLAUDE.md`「Gitバックアップ」）、いつ何が変わったかも追える。**転記して要点をmdに書くだけでは、原本の情報（数式・書式・転記時に落とした列）が失われる。**

## 何を保存するか

- 会計・給与・税務の資料（Excel・PDF・CSV・画像・スクリーンショット）
- 取引先とのやりとりの原本（メール本文、Slackの重要スレッドの転記）
- 手順書・メモの類（オーナーが手元で管理していたもの）
- チャットで口頭で伝えられた事実・ルール・判断（該当する `context/` や `.claude/rules/` に文章として書く）

## どこに置くか

- 対象クライアントが決まっているもの → そのインスタンスの `context/company/source/`（原本）。要点は同じ `context/` 配下のmdに書く
- 全クライアント共通の知見 → `.claude/rules/` または `docs/`
- 一時的な作業ファイル（中間生成物・ログ）は対象外。従来どおり `work/` かスクラッチパッドへ

## 保存するときの作法

1. **原本をそのまま置く**（拡張子も元のまま）。ファイル名は内容と対象会社が分かる名前にする（例：`給与計算メモ-○○.xlsx`）
2. **中身をmdに転記する**。バイナリはgitで差分が見えず検索もできないため、原本だけでは後から使えない
3. 転記先に**出典（元のパス・受け取った日）を書く**
4. commitして**pushまで行う**（ルート`CLAUDE.md`「git commitするたびにpush」）

## 保存してはいけないもの

- 認証情報（`.env`・トークン・パスワード・APIキー・秘密鍵）。`security.md`のhooksがブロックする対象
- 保存の可否に迷うもの（第三者の個人情報が多量に含まれる名簿など）は、置く前にオーナーに一言確認する

## 二重管理を避ける

オーナーが手元で更新し続けている資料をリポジトリにも置くと、**どちらが最新か分からなくなる**。取り込んだら「今後の変更はチャットで一言もらえれば私が反映します」と伝え、リポジトリ側を正にしていく。原本は受け取った時点のスナップショットとして残す。
