# ミス対応の原則（全クライアント共通）

このファイルは、使いながら追記していく場所です。

## 基本原則

自分の作業でミス・誤りが発覚した場合（オーナーの指摘によるものも、自分で気づいたものも含む）、その場で該当箇所を直すだけで終わらせず、**必ず原因を追究し、次に同じミスが起きないための対応まで行う**こと。

**How to apply:**
1. 何が起きたか（事象）だけでなく、なぜ起きたか（原因）を特定する。表面的な操作ミスに見えても、「なぜその操作ミスをしたか」まで遡って考える（例：手順の勘違い、確認不足、ツールの癖の見落とし等）。
2. 原因に応じた再発防止策を講じる：
   - 手順・ツールの癖に起因するもの → 該当スキルのSKILL.mdや技術メモに、正しい手順と失敗パターンの両方を記録する
   - 判断基準の誤り・抜けに起因するもの → 該当ルール（accounting-rules.md等）を修正・追記する
   - 継続的に見落としうる種類のミスで、機械的にチェック可能なもの → 月次チェックリスト等の定型チェック項目に追加し、次回以降は自動的に気づける仕組みにする（`monthly-closing-checklist.md`参照）
3. 記録先はミスの性質で使い分ける：
   - 特定クライアントの業務ルール・データに起因するミス → そのクライアントインスタンス内（`context/company/accounting-rules.md`、各スキルのSKILL.md）
   - ツールの操作方法・技術的な癖など、クライアントを問わず起こりうるミス → 該当スキルの技術メモ、またはこのファイル
   - AI秘書としての仕事の進め方そのものに関わる教訓 → `.claude/rules/`配下（このファイルを含む）、またはメモリ

**Why:** 会計システムへの登録で「保存の成否確認が不十分だったために同じ処理を繰り返し、貸方が重複計上される」型の事故は典型例。**1件登録→レスポンスで結果を確認→次の1件**のサイクルを徹底し、まとめて登録して後から気づくことがないようにする。

## 典型的な失敗パターン（教訓の蓄積）

- **保存の成否を確認せずに再実行する**：API・画面操作とも、成功したかどうかを必ずレスポンスや再取得で確認してから次に進む。確認できないまま再試行すると二重登録になる
- **他社の実績IDをそのまま流用する**：勘定科目ID・補助科目ID・税区分IDは会社ごとに別物。会社を切り替えるたびに必ず取り直す
- **金額一致だけで消込先を決める**：同額の候補が複数ありうる。取引先・補助科目・計上時の内容まで一致を確認する
- **課税仕訳の検算でvalueだけを比較する**：内税入力の会計システムでは、登録後に本体（value）と消費税（tax_value）に分解されて返る。借方・貸方の一致は`value＋tax_value`で比較しないと、正しい仕訳を「不整合」と誤診断する
- **会計期間をまたぐデータを仕訳番号でマージする**：仕訳番号は会計期間ごとにリセットされる会計システムがある。必ずシステム固有のユニークIDでマージする
